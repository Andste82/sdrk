# Testing with virtual devices and the loopback channel

The testkit (`sdrk-testkit`, layer `crates/testing`) has virtual devices for the stream traits and a channel simulator. Unit tests of the crates, the driver conformance checks ([device.md](device.md#conformance-checks)) and the system tests of phase 3 use them.

## Virtual devices

- `VirtualRx` (M03): a deterministic signal source delivered in chunks, with gaps and an anchor.
- `VirtualTx` (`no_std`): `TxStream` that stores what is written in caller storage, records every call (start, flags, `tx_time_ns`, sample count, position; at most 64 calls) and injects `UNDERRUN` and `LATE` statuses for `poll_status` at configured sample indices.

## Loopback channel

`channel::Loopback::new(LoopbackParams)` returns the two sides of a channel: `LoopbackTx` (a `TxStream`) and `LoopbackRx` (an `RxStream`), connected through shared state (`split()` gives the two sides, both are `Send`). They share a timeline: receive index 0 is the time `t0_ns`. At the receive index `n` the channel produces

```text
y[n] = g * x(n - d) * exp(j 2 pi f n / fs) + noise[n],     g = 10^(-attenuation_db / 20)
```

- `x` is the transmitted signal in `f64`, placed on the timeline: a write with `tx_time_ns` starts a burst at the index `round((tx_time - t0) * rate / 1e9)` (exact integer arithmetic; a burst before `t0` is dropped and reported as a `LATE` status), a write without a time continues the current burst, and continuous transmission starts at index 0. `BURST_END` closes the current burst. Overlapping bursts add. Silence is zero.
- The delay `d = delay_samples`: the integer part shifts the index, the fractional part is a 63-tap Kaiser(beta 8)-windowed-sinc interpolator computed in `f64` (`g[j] = sinc(j - frac) * kaiser(j - frac)`, `j = -31..31`). An integer delay is an exact shift; silent stretches cost nothing.
- The frequency offset `f` rotates by the phase `2 pi frac(f n / fs)` of the absolute index.
- The noise has independent normal I and Q components of the standard deviation `noise_sigma` (units: 1.0 is full scale). It comes from PCG32 positioned by the absolute index (8 draws per sample, Box-Muller), so any chunking gives the same samples; `seed` selects the sequence.
- The result is encoded into the raw format with saturation. The format must have a whole number of bytes per sample.
- The receiver never ends. It produces what the transmitter has written so far: transmit first, then receive. The first receive block carries the anchor `index 0 = t0_ns` (source `Host`).

## Channel impairments, PSK test signal and BER meter (M38)

The digital-mode tests (M38 to M44) build their channel from sample-stream impairments in `channel` (feature `std`), next to `Loopback`. Each implements the trait `Impairment` (`process(&mut self, input, output)` appends to `output` and keeps the state, so chunked processing equals processing at once); all work on `Complex64` (a real signal is the real part).

| Type | Model |
| --- | --- |
| `Awgn::new(sigma, seed)` | adds independent normal I and Q of the standard deviation `sigma` (Box-Muller from `Pcg32`, I first) |
| `Awgn::from_ebn0(ebn0_db, bits_per_symbol, sps, signal_power, seed)` | `sigma^2 = signal_power sps / (2 bits_per_symbol 10^(ebn0_db / 10))` per component (`signal_power` is the mean power per sample; `N0 = 2 sigma^2`) |
| `FrequencyOffset::new(offset_hz, fs)` | multiplies sample `n` by `exp(j 2 pi frac(offset_hz n / fs))` (phase in f64 from the index) |
| `ClockDrift::new(ppm)` | output `m` is the input at the position `m (1 + ppm 1e-6)`, interpolated in f64 by a windowed sinc with 32 taps per side (4-term Blackman–Harris window; measured error below 1e-6 for tones up to 0.3 cycles per sample, the test requires 1e-5); an event at the input position `q` comes out at `output_position(q) = q / (1 + ppm 1e-6)`; zero drift is an exact identity |
| `ChannelChain` | applies a list of impairments in order (`new().with(a).with(b)`) |
| `Multipath::new(&[(delay_samples, gain)])` (M43) | `y[n] = sum g x(n - d)` over the taps (delay `0 ..= 65536` samples, complex gain), an integer delay exact, a fractional one through the windowed sinc of `ClockDrift`, combined into one impulse response (`response()`); a fractional delay `d` below 32 samples looks ahead, so the first `lag() = 31 - floor(d)` inputs (the largest over the taps) give no output; a single tap at delay 0 is an exact identity (D810) |
| `Multipath::mild(sps)`, `Multipath::severe(sps)` (M43) | the presets of M43 section 4 (`Multipath::MILD`: `1`, `0.3 e^(j1)` after 1.3 and `0.1 e^(-j2)` after 2.7 symbols; `Multipath::SEVERE`: `1`, `0.6 e^(j0.5)` after 0.8, `0.4 e^(-j1.5)` after 2.1 and `0.2` after 4 symbols) with the delays scaled by `sps` samples per symbol (1 on the symbol stream) |

`r#gen::PskTest` (and the shortcut `r#gen::psk_test`) makes the BPSK/QPSK test signal: symbol `k` (BPSK `2b - 1`; QPSK Gray, bit `2k` to the real and bit `2k + 1` to the imaginary part, each `(2b - 1) / sqrt(2)`) centred at the sample position `offset + k sps`, shaped with a raised-cosine (default) or root-raised-cosine pulse of roll-off `rolloff` truncated to `span` symbols per side (default 16), computed in f64 from the absolute sample index. `r#gen::pulse` evaluates the two pulses (for a matched filter in a test).

The test bits come from `sdrk_proto::prbs` (M38): `Prbs::new(Poly::Prbs9 | Poly::Prbs15, seed)` is a Fibonacci LFSR (`x^9 + x^5 + 1`, `x^15 + x^14 + 1`) whose output bit is the feedback bit; `next_bit()` returns 0 or 1, a seed whose low 9 or 15 bits are zero is `InvalidArgument` (D538), and `Poly` gives `degree()`, `period()` (511, 32767), `feedback(state)` and `shift(state, bit)`. `sdrk-proto/tests/prbs.rs` checks the first 32 bits of both sequences from the all-ones seed and the maximal period.

`ber::BerMeter::new(poly, seed)` (`no_std`) measures the bit error rate of a PRBS of `sdrk_proto::prbs` from hard bits: it locks to any phase of the sequence after 32 correct predictions in a row (self-synchronizing; the seed only gives the first prediction), then counts `bits()` and `errors()` with its own register; 64 errors within the last 128 counted bits count a `slips()` and restart the acquisition (the bits counted before stay counted). `push(bit)` and `push_bits(&[u8])` take hard bits (any non-zero value is 1), `is_locked()` tells the state, `ber()` and `confidence_95()` (Wilson score interval) give the result. `sdrk-testkit/tests/channel_ber_m38.rs` holds tests 5 and 6 of M38: the meter with injected errors (exact count) and with a slip (seed 497, D544), `Awgn::from_ebn0` within 0.1 dB of the requested Eb/N0 over 10^6 samples (seed 498), `FrequencyOffset` and `ClockDrift` against analytic tones (seed 499), the chunk invariance of the impairments and the mapping and power of `PskTest`.

The end-to-end tests of `symbol_sync` use these models: `sdrk-testkit/tests/e2e_symbol_sync_m38.rs` holds the lock test (Gardner, raised cosine 0.35, start half a symbol off, ±100 ppm, sps 2, 4, 4.1 and 10.1; every strobe from 500 to 1499 within 0.05 symbols of the generator's symbol centre, seed 494) and the BER tests (PRBS-15 BPSK, root-raised-cosine transmitter and matched filter, 50 ppm, Eb/N0 6 and 8 dB, 10^6 counted bits each: Gardner at sps 4.1 within a factor 1.5 of `Q(sqrt(2 Eb/N0))`, seed 495; Mueller–Müller at sps 2 within a factor 2, seed 496). The lock test and the Gardner BER test run with the block default `ted_gain` 1.0, the Mueller–Müller BER test with its detector slope per symbol, 1.78 (D565). The BER tests are the slowest of the milestone in the unoptimized test profile (per test 2 x 10^6 counted bits, generated with the f64 pulse, the 64-tap drift interpolator and a matched filter of 131 taps at sps 4.1 or 65 taps at sps 2, D561); run them with `--nocapture` to see the measured BER, the theory and the 95 % interval. ## Carrier recovery tests (M40)

`sdrk-testkit/tests/costas_lock_m40.rs` holds test 4 of M40: the Costas loop of order 4 with the defaults (`loop_bw` 0.02, `damping` 0.7071, `max_offset` 0.05) on random QPSK with one sample per symbol, turned by 8 start phases (multiples of 45 degrees plus 10) and by 0.01 cycles per symbol with `FrequencyOffset`, plus `Awgn` for Eb/N0 10 dB (seed 557). Locked within 500 symbols means: the lock detector is on at symbol 500 and stays on, the integrator ends within 0.002 cycles per symbol of the offset, and from symbol 500 on the outputs are the transmitted symbols turned by one fixed multiple of 90 degrees (the ambiguity of QPSK) with at most 2 symbol errors and a mean phase error below 5 degrees in every window of 100 symbols (single symbols spread by about 9 degrees with this noise, D611). The second test feeds noise alone (the detector never turns on over 3000 symbols) and noise after a locked signal (the detector turns off within 500 symbols). The golden, unit and suite tests of the kernel are listed in [kernels.md](kernels.md#costas).

`sdrk-testkit/tests/psk_ber_m40.rs` holds tests 2 and 3 of M40 (D618, D619): PRBS-15 soft bits through `PskModBlock` (4 samples per symbol, 10 kBd, roll-off 0.35, span 10), `FrequencyOffset` of 0.002 cycles per symbol, `ClockDrift` of 50 ppm and `Awgn::from_ebn0` (the measured mean power, 1.000) into `PskDemodBlock` with its defaults. After 2000 symbols of acquisition exactly 10^6 bits are counted per Eb/N0 point (6 and 8 dB) by one `BerMeter` per phase hypothesis (both polarities for BPSK, the four rotations for QPSK: a quarter turn maps `(b0, b1)` to `(!b1, b0)`); the meter that synchronizes is the result and no meter may slip. Coherent BPSK (seed 553) and QPSK (seed 554) must lie within a factor 1.5 of `Q(sqrt(2 Eb/N0))`, DBPSK (seed 555) and DQPSK (seed 556) within 1 dB of their theory (between the theory at Eb/N0 + 1 dB and - 1 dB; DQPSK with the exact Gray formula with the Marcum Q function). Measured: BPSK 1.28 and 1.24 times the theory at 6 and 8 dB, QPSK 1.24 and 1.34, DBPSK 1.16 and 1.18, DQPSK 1.04 and 1.09, no slips. The two Eb/N0 points of a test share the transmitter and run on two threads; in the unoptimized test profile a test takes about 40 s (QPSK) to 77 s (BPSK). They stay in the default test run (as the BER tests of M38, D561).

`sdrk-testkit/tests/psk_ber_m40_1.rs` holds tests 2 to 4 of M40.1 with the chain of `psk_ber_m40.rs` (D654 to D657, D659, D685 to D688). 8PSK (seed 561) at 12 and 14 dB with one meter per eighth turn (the rotation is undone on the Gray code with `PSK8_GRAY`) must lie within 1 dB of `(2/3) Q(sqrt(6 Eb/N0) sin(pi/8))`; the lower edge is checked only where the theory expects at least 10 errors in the 10^6 bits, so at 14 dB (0.9 expected errors) only the upper edge counts (D654). pi/4-DQPSK (seed 562) at 6 and 8 dB must lie within 1 dB of the DQPSK theory. OQPSK (seed 563) at 6 and 8 dB runs with the carrier offset of 0.002 cycles per symbol and the 50 ppm drift of M40 next to plain QPSK through the same chain, and its BER must lie within a factor 1.5 of the QPSK BER (D657, D688); its four meters undo the half turn (both bits inverted) and the quarter turns, which pair the quadrature bit of the previous symbol with the in-phase bit of the current one (one of the two inverted, D655). `oqpsk_corrects_constant_phases_and_acquires` runs OQPSK at 8 dB over 2 10^5 bits with the constant carrier phases 0, 0.3 rad and pi/4 (no slips, each within a factor 1.5 of aligned plain QPSK) and checks the acquisition of the OQPSK loop without noise (pi/4 plus 0.002 cycles per symbol and the drift: lock within 1000 symbols and kept, frequency within 2e-4, D688); `psk8_demod_locks_on_8psk_and_not_on_noise` checks that order 8, as order 4, never locks on noise and locks on 8PSK turned by 1 rad (D659). The envelope tests measure the `psk_mod` output at 16 samples per symbol without `span sps` samples at each end (D656): pi/4-DQPSK `min |y| >= 0.12` for roll-off 0.35 over all samples (measured 0.135; the bound of the maintainer's decision D685, which replaces the 0.2 of the first specification) while plain QPSK reaches 0; OQPSK `min |y| >= 0.3 mean |y|` (measured 0.446) and above the ratio of plain QPSK (0). The measured figures are in the Status section of the milestone; the file takes about 45 s in the unoptimized test profile.

`sdrk-pipeline/tests/qpsk_loop.rs` holds test 5 of M40 (D623): 1000 packets (0 to 63 random bytes, seed 558) pulled from the example flow `qpsk_transmitter` after 20000 idle symbols, the `cs8` output shifted by 2 kHz (`FrequencyOffset`) and given noise at Eb/N0 10 dB (`Awgn::from_ebn0` with the measured transmit power, seed 558), rounded to `cs16` and pushed into `qpsk_receiver`. Coherent QPSK locks on one of four phases and `frame_decode` `polarity` both resolves only 180 degrees, so the receiver runs on the channel output rotated by 0, 90, 180 and 270 degrees (exact swaps and negations; the receiver is equivariant to them), in four threads: the two rotations that put the lock on 0 or 180 degrees must give at least 995 packets with `CRC_OK` and unchanged payload, and the same packets; the other two give none. Measured: 998 of 1000, about 20 s in the test profile. The test also checks that one-sample pulls of the idle transmitter equal one large pull (D620).

## ISM band transmissions (M45.1)

`sdrk_testkit::ism` generates the bursts of short-range devices for the band receiver of M45.1. A `Transmission` sends its `bits` `repeats` times in one of four codings: `Pwm` (a 1 is a pulse of `short_us`, a 0 one of `long_us`, every pulse followed by `gap_us`), `Ppm` (pulses of `pulse_us`, a 0 a gap of `short_gap_us`, a 1 one of `long_gap_us`, a final pulse ends the last gap), `Manchester` (a 1 is carrier on then off, a 0 off then on, `half_bit_us` each) and `Fsk` (NRZ, a 1 at `freq_offset_hz + deviation_hz`, a 0 at `freq_offset_hz - deviation_hz`). A copy ends with its last time of carrier on; the next copy starts `repeat_gap_us` later, carrier off in between; every duration is scaled by `1 + timing_error`. `Transmission::runs` lists the result as runs of `Level::Off`, `On`, `Low` or `High` (equal neighbours joined), the description a detector has to recover. `Transmission::render` adds the burst to a `C32` buffer: the OOK envelope has a raised cosine of 2 µs (`RISE_US`) centred on every edge, so it crosses half the amplitude exactly at the nominal edge, and the FSK phase is the exact integral of the frequency, continuous at every bit transition (also within a sample). A `Scene` places up to 64 transmissions at start times and adds complex Gaussian band noise (`noise_db`, the total power in dBFS), up to 16 interferers (`Interferer::Carrier`, a CW carrier over the whole scene; `Interferer::WidebandBurst`, Gaussian noise over the whole band for a while) and the receiver's clock error `clock_error_ppm`: sample `n` is the true time `n / (fs (1 + e))` and every carrier moves by `-center_hz e` (`Scene::apparent_offset_hz`, `Scene::apparent_us` and `Scene::noise_db_in` give what the receiver measures). The random streams are `Pcg32::new(seed, 0)` for the band noise, `Pcg32::new(seed, 1 + i)` for interferer `i` and `Pcg32::new(seed, 0x1_0000 + i)` for the start phase of transmission `i`; the `SceneRenderer` evaluates every sample from its index, so any chunking gives the same samples. Unit tests in `ism.rs`: the runs of every coding with repeats and timing error, the rendered OOK edges at half amplitude within 0.05 µs of the nominal times, the two FSK frequencies and the continuous phase across a transition, the clock error, the noise, carrier and burst levels, chunk invariance and the seed.

## The SIMD backend in the suite and in CI

**E2E-STEREO (M24).** `sdrk_testkit::e2e_stereo` receives a stereo broadcast (2.4 MS/s, +600 kHz, deviation 75 kHz, `L` 1 kHz and `R` 3 kHz at amplitude 1, pilot 0.1, scaled to 0.9, complex noise sigma 0.003, `CU8`) with the blocks `convert`, `ddc` (decimation 5, cutoff 130 kHz, transition 30 kHz) and `fm_stereo_demod` and measures from 0.25 s on without storing a sample: `MultitoneAccumulator` (the normal equations of a joint least-squares fit of 1 kHz, 3 kHz and the 19 kHz pilot per channel) gives the separation (`f32` at least 40 dB, Q15 at least 35 dB), the SINAD per channel with both tones removed (55 and 45 dB), the level against `0.9 |H_de|` within 0.5 dB (Q15 scaled by `2 deviation / fs`, the unit of the Q15 discriminator) and the pilot residue (at most -70 and -60 dBFS); `pilot_locked()` is polled after every block of 500 samples and must become true within 0.1 s and stay true. The switching case (pilot from 0.3 s to 0.7 s of 1.0 s) needs stereo within 0.1 s after the pilot appears, mono within 0.2 s after it vanishes and bit-identical channels while mono; the mono cases (a mono transmission, noise without a carrier) never report stereo. The pilot of the switching signal is gated by adding its phase integral over the window (`StereoSignal::switching`; the edges are multiples of 1 ms, i.e. whole pilot periods, so the multiplex signal stays continuous). The cases `block_fm_stereo_demod_separation` and `block_fm_stereo_demod_mono` (the block alone at 480 kHz) and the E2E cases `e2e_fm_stereo_f32` and `e2e_fm_stereo_q15` (0.5 s) are in the quick profile; `e2e_fm_stereo_mono` (0.25 s each of a mono transmission and noise), `e2e_fm_stereo_{f32,q15}_2s` and `e2e_fm_stereo_switch_f32` are in the full profile, because the signal at 2.4 MS/s with a nine-term multiplex generator is expensive on the Cortex-M4 (the quick profile takes 728 of its 900 s with them, decision D128). The host numbers are in `crates/testing/sdrk-testkit/tests/e2e_stereo_m24.rs`.

**Loop tests (M25).** The three groups in `tests/system/tests/loop_fm_m25.rs` (table above) feed the `cs8` bytes of the transmitter flow, pulled in pull mode, into the receiver flow without a channel and measure the audio with `ToneMeter` and `sinad_db`. The peak is measured by a separate small flow (`ddc` from 2.4 MS/s to 240 kS/s and `fm_demod` with `deemphasis_us` 0 and `audio_decimation` 1, i.e. `quad_demod` with the gain `240 kHz / (2 pi deviation_hz)`, always in `f32`, because the Q15 discriminator cannot read above 1.0). The noise is generated in the test: `Pcg32::new(450, 1)`, a fourth-order Butterworth low-pass at 15 kHz (two RBJ sections in `f64`), scaled to sigma 3 after the filter. For Q15 the flow gets `settings.precision` `q15` and `inputs.audio.type` `q15` (the input type must fit the precision) and a pull source that converts with saturation. They need the pipeline and therefore `std`, so they are not suite cases and cost no emulator time; they take about 35 s in a debug build. The suite cases of M25 (kernel cases `preemph_limit_f32` and `preemph_limit_q15` with `Fallback` against `Reference` and 20 chunk plans, `block_preemph_limit_peak` with random input up to 20 times full scale, all quick; `extremes_m25`, full) are listed in `crates/testing/sdrk-testkit/src/cases.rs`; `tests/suite_m25.rs` runs them on the host in both profiles and in the 80 KiB arena of the quick profile.

**Loop tests (M35).** `crates/testing/sdrk-testkit/tests/e2e_loop_m35.rs` (feature `std`) chains the blocks without a channel at 48 kHz with a 1 kHz tone 0.5: LOOP-AM `am_mod` (defaults) into `am_demod` (defaults), LOOP-SSB `ssb_mod` into `ssb_demod` (same band) for USB and LSB, in `f32` and Q15. The first 0.1 s of every output is skipped and 1 s measured; the opposite-sideband rejection is the RMS ratio of the two demodulator outputs and the frequency checks use a 4800-point DFT, on whose bin 100 the tone lies exactly (D436). Measured (D437): LOOP-AM SINAD 125.88 dB (`f32`, needs 40) and 81.67 dB (Q15, needs 30); LOOP-SSB level +0.0005 dB and +0.0047 dB (allowed 0.5 dB), opposite sideband 82.56 dB and 74.70 dB lower (needs 50), mirror of the `ssb_mod` output -88.58 dB and -113.88 dB (needs -50). They take about 50 s in a debug build and are not suite cases.

The suite of `sdrk-testkit` runs through the facade, so every case exercises the SIMD backend where the platform has one. Fifteen cases `backend_vs_fallback_*` (`convert`, `convert_out`, `rotate`, `fir`, `fir_decimate`, `fir_interpolate`, `biquad`, `mag_sq`, `mag`, `quad_demod`, `fm_mod`, `fft`, and the M23 cases `halfband` for `halfband_decimate` and `halfband_decimate_real`, and `real_to_complex`, and the M24 case `stereo_matrix`) cover every accelerated kernel and type (the `C32` `agc` is compared with the fallback bit for bit by its own case `agc_c32`) with the lengths 0, 1, 3, 15, 16, 17, 255 and 4096 (the lengths that fit the arena of the tier: the quick tier takes the short ones), extreme inputs (full scale, -32768, NaN and infinity in `f32` where defined) and, for the stateful kernels, random chunk plans that must give the bits of one call. Bit-exact kernels are compared bit for bit with the fallback; tolerance kernels with the contract of `docs/kernels.md` against the reference (`rotate` 120 dB, `fir` family 110 dB, `quad_demod` 100 dB / 2 LSB, `fft` 110 dB for `C32`; for `CQ15` the exact transform is the measure, fixed scaling within 1 dB of the fallback with its exponent and block floating point checked by the reference cases of M07, `fm_mod` 120 dB; the `C32` and `f32` halfband and `real_to_complex` kernels 110 dB against the reference, the `Q15` and `CQ15` ones bit for bit with the fallback including the full-scale saturation corners, and `real_to_complex` also over random chunk plans that must keep the phase across calls).

The tests of the crate `sdrk-backend-simd` (`crates/backends/sdrk-backend-simd/tests`) compare the kernels with the fallback for all lengths of the vector tails, with `LENGTHS = 0, 1, 2, 3, 7, 15, 16, 17, 31, 255, 257, 4096` (`mag` and `mag_sq` at every length up to 4096 and at four start offsets; the `mag` CQ15 integer square root also around every perfect square and every rounding boundary `r (r + 1)`, and in the ignored test `mag_cq15_exhaustive_every_raw_pair` for all 2^32 raw pairs, run by the `sweep_*` jobs), with random chunk plans, extreme inputs and invalid calls (same error values as the fallback). They run at the level the build selects: the default build at SSE2, `--features std` at the best level of the CPU, `-C target-cpu=...` at the level of the flag. A workspace run enables `std` of the backend (the pipeline, `sdrk-testkit/std` and the system tests ask for it), so it always detects the level at run time; the static levels are tested with the backend and the facade alone (`cargo test -p sdrk-backend-simd -p sdrk`). The backend alone (without `-p sdrk`) also runs its own default build, without the static tables `nco-tables` and `fft-tables`, which the facade switches on. `SDRK_EXPECT_LEVEL=<name>` makes `tests/api.rs` check that `level_name()` is that level; every CI step that tests a level sets it, so a build or an emulator that selects another level fails instead of passing at the wrong one. The exhaustive test of `convert_out` (`convert_out_exhaustive_every_f32`, every `f32` bit pattern against the fallback, the proof of the per-byte CU8 bound) is `#[ignore]` and runs nightly in the jobs `sweep_*`; `SDRK_SWEEP_PART=k/n` runs the `k`-th of `n` interleaved parts, each of which covers every exponent.

`sdrk::backend_for` is tested in `crates/facade/sdrk/tests/facade.rs`: every accelerated kernel reports `simd` when `sdrk::SIMD_BACKEND` is true and `fallback` otherwise (`--cfg sdrk_fallback_only`, no `simd` feature, or a target without SIMD).

### CI

CI is three workflow files. `ci.yml` runs on pull requests and on pushes to `main`, `nightly.yml` every night and on demand, and both call `tree.yml`, the tree of jobs. A job starts when the jobs it needs have passed; when one fails or is skipped, everything below it is skipped too.

| Trigger | File | What runs |
| --- | --- | --- |
| pull request | `ci.yml` | `scope` (what changed), then the tree with scope `pr`: `check`, every build and the tests marked `pr` below. A pull request that only changes Markdown files no test reads runs `check` only |
| `gh workflow run nightly.yml --ref <branch>` | `nightly.yml` | the tree with scope `full` on any branch, for example before merging a change of the CI or of a long-running job |
| push to `main` | `ci.yml` | `smoke` (build, `xtask check`, `bare-metal`, the unit tests). The pull request has tested the same tree, because a branch must be up to date with `main` before it is merged |
| every night | `nightly.yml` | the tree with scope `full`: every `pr` job and the jobs marked `full`. When `main` is unchanged since the last green nightly run, the `pr` tests are skipped and only the `full` jobs run, except on Sunday |
| Sunday night | `nightly.yml` | as every night, with the `pr` tests always |
| manual (`workflow_dispatch`) | `nightly.yml` | as at night; the input chooses whether the `pr` tests are skipped |

The branch protection of `main` requires one check, `result` of `ci.yml`: it is green only when `scope` and every job of the tree that ran passed, and the branch is up to date with `main`. A failed nightly run opens an issue with the label `nightly-failure`, or comments on the open one. Every job has a timeout; the cargo caches are saved by runs on `main` only (pull requests read them), one cache per platform and build.

The tree, with `[pr]` for every run and `[full]` for nightly and manual runs. The SIMD variants that depend only on the CPU architecture (fixed levels, without the static tables, fallback only) run on one host per architecture: x86-64 on Linux, AArch64 on Linux arm64. The test programs are built once per platform. The build job packs them with `cargo nextest archive`; the test job of the same platform downloads the archive, extracts it into its checkout (the same path, so the paths the tests compiled in stay valid) and runs it without building. nextest does not run doc tests, so `build_x64_linux` runs them with `cargo test --doc`. The jobs that need other flags (fixed levels, the fallback, the sweeps in release) build themselves; their cargo caches are separate.

## The suite on microcontrollers

The `no_std` suite of the testkit (`all_cases()`, `run_suite`, the line protocol) runs bare-metal in five emulators: a Cortex-M4F (every commit), a Cortex-M55, RISC-V `rv32imac` (nightly), the ESP32-P4 and the ESP32-S3 (paused in CI, D201; local runs only), with the quick and the full profile. `cargo xtask emu` builds, runs and judges them; the CI jobs are `build_m4_qemu` (every pull request), `build_*_qemu` (build only, every pull request) and `test_emu` (nightly). See [embedded.md](embedded.md).
