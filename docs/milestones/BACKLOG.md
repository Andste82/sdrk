## Phase 7 — further embedded backends (same recipe as M13/M16)

The RISC-V Vector backend is milestone [M17](M17-rvv-backend.md), the Arm DSP-extension backend (Cortex-M4/M7/M33, also the RP2350) is [M18](M18-arm-dsp-backend.md). Left for the backlog from it: 32-bit RISC-V with `V` and the embedded subsets `Zve32f`/`Zve64f` (no 64-bit lanes: the CQ15 filters need a chunked or fallback path), vectorised `quad_demod` and `fm_mod`.

## Phase 8 — further bindings (optional, only on concrete demand)

- **C bindings** (`bindings/c`): `extern "C"` API mirroring the WASM API (pipeline from JSON, push/pull, outputs, events, params), opaque handles, error codes = `ErrorKind` numbers, header generated with `cbindgen` (checked in, verified by CI).
- **Python bindings** (`bindings/python`): PyO3 + maturin, NumPy arrays without copy (`numpy` crate), same API shape; wheels for the three host platforms.
- Rule since M10: the public API stays binding-friendly (plain types, errors instead of panics, fixed sample-type variants next to generics); the WASM bindings keep this tested.

## Phase 9 — stabilization and extensions

- **Platform-independent golden vectors:** the generator produces other bits on Windows and Linux arm64 in about 40 cases (Windows: `fft` 18, `design` 6, `rotate` 5, `fm_mod` 4, `window` 3, `blocks` 2, `quad_demod` 2, `power_db` 1; arm64: `fft` 18, `design` 3, `blocks` 2, `fir` 2, `fir_decimate` 2, `window` 1; CI run 40194336676), because NumPy and SciPy use the math library of the platform. Compute the transcendental functions, the FFT reference and the filter design of those cases with own scalar code (`sdrk_golden/scalar_math.py`, as M09 did for `dot`, `blocks` and `kaiserord`), then make `golden_x64_win` and `golden_arm64_linux` compare byte for byte and drop the Linux-only rule of `tests/golden/README.md`. Maintainer decision of 2026-10-25: do this next.

- **Driver conformance suite complete** (all capabilities of M12, timed commands, async streams) and **`sdrk-device` 1.0** (API review, semver promise, MSRV policy).
- **Kernels and blocks** (squelch, AGC, AM, SSB, `biquad`, halfband decimation and `real_to_complex` are the milestones [M19](M19-nfm-squelch.md) to [M23](M23-real-sampling-input.md), FM stereo is [M24](M24-fm-stereo.md), FM pre-emphasis and limiter for transmitting are [M25](M25-fm-transmit-audio.md)): `iq_balance` (IQ imbalance correction), `sigma_delta_decimate` (SX1255 mode A, 1-bit `Bits1` container from M01), CIC (decimate/interpolate), halfband interpolation by 2, CTCSS tone generation, transmit loudness processing (compressor, look-ahead limiter), soft stereo blending and the stereo indicator as a pipeline event (left out of M24). (Now milestones: two-input nodes M34, FM stereo transmission M36, pulse shaping (RRC) M40, RDS M41 and M42.)
- **FFT extensions:** Q15 real FFT and its inverse. (FFT-based fast convolution / overlap-save is now the kernel `xcorr_fft` with the block `correlate`, [M50](M50-xcorr-fft.md); a `sync_detect` block over it (peak search, threshold) stays in the backlog.)

- **Spread spectrum and multicarrier — kernels and their primitive blocks scheduled (M48–M56), composite blocks and flows to follow:** the DSSS/OFDM kernel series delivers the signal-processing primitives one per milestone, each with its primitive block and pipeline kind — `gauss_noise` (M48), `scramble` (M49), `xcorr_fft` (M50), `spread` (M51), `despread` (M52), `code_search` (M53), `code_track` (M54), `pilot_equalize` (M55), `fwht` (M56). Still backlog on top of them: the `sdrk-proto` side (a general LFSR — M49 only adds the PRBS polynomials of degree 5, 7, 10 and 11 to `sdrk_proto::prbs` — Gold/Kasami/Walsh codes, a keyed ChaCha20 keystream with random access, FEC — convolutional + Viterbi, then LDPC — as `fec_encode`/`fec_decode`); the blocks and kinds above the primitives (`code_acquire`, `sync_detect`, `dsss_mod`/`dsss_demod`; `fft`/`ifft`/`to_lanes`/`from_lanes`/`subcarrier_map`/`ofdm_mod`/`ofdm_demod` on lanes; `freq_spread`/`freq_despread`); the detector bank for LPD/LPI measurement (`energy_detect`, `autocorr`, `cyclo_spectrum`, the `conjugate_b` option of `mul`, ROC and Gaussianity tests in the testkit); frequency/time hopping; FBMC with a synthesis filter bank; CQ15/Q15 variants for embedded. (The full gap analysis for the LPD/LPI research direction lives in the project notes, `analysen/lpd-lpi-ofdm-dsss-gap-analyse.md`.)
- **Analysis blocks** with structured results (frames/events): signal detection (frequency, bandwidth, level, SNR), occupied bandwidth, noise floor, burst detection, instantaneous values and histograms, symbol-rate estimator.
- **Digital modes after M44:** diagram data as frames (constellation, eye diagram); `sync_detect` (a sample-level preamble correlator; M37–M44 synchronize on bits); forward error correction (convolutional codes with Viterbi, Reed–Solomon, LDPC); CQ15/Q15 variants of the digital blocks (M38–M44 are C32/f32 only); fractionally spaced and decision-feedback equalizers; 256-QAM and APSK; protocol stacks (POCSAG, M17, DMR framing, FX.25, G3RUH 9600 Bd, APRS payload parser, ADS-B CPR positions and error correction, device decoders for OOK sensors); RDS error correction, RDS2, ODA/TMC; LoRa (CSS), OFDM (DAB, DVB-T, WLAN), spread spectrum.
- **Plans of the composite blocks (the original M32, moved here by D358):** for `ddc`, `duc`, `fm_demod`, `am_demod`, `ssb_demod` and `fm_stereo_demod` the same computation as a composition of primitive blocks with `Chain` and `Fork` (module `sdrk_blocks::plans`), equal to the block bit for bit on every backend, as an executable specification. Nice to have: the blocks are already checked against golden cases and kernel chains, and the first new composite block (M35) can be written as a plan when it is built.
- **Optimized square-root Nyquist pulse shapes (from M40, D626):** a `design` mode next to `rrc` for pulse shapes with lower intersymbol interference at the same length: a Kaiser-windowed RRC whose bandwidth is tuned so that `h * h` is close to Nyquist (as liquid-dsp's `rkaiser`, with the closed-form approximation of `arkaiser`), or a Harris-Moerder design; a parameter `shape` (`rrc`/`rkaiser`) of `psk_mod` and `psk_demod`. The truncated RRC leaves about -45 dB at span 10 (5.8e-3 at roll-off 0.35, 8 samples per symbol); a tuned Kaiser design reaches about -65 dB at the same length with a slightly wider effective roll-off. Build it when a mode needs more than -45 dB, for example dense QAM after M44, and gate it against liquid-dsp.
- **`biquad` with explicit coefficients (from M34, D398):** a mode of the kind `biquad` that takes `b0, b1, b2, a1, a2` per section instead of a response (schema mode, a stability check, the Q15 coefficient range), for filters the RBJ responses do not cover: the pre-emphasis of the FM stereo transmitter (M36), shelving and all-pass sections, designs from an external tool. Build it when a block needs it.
- **Composition (from M27–M34):** a generic kernel merge so that `fir_decimate` has a real variant (`FirDecimateReal`; M29 uses `resample_real` with L = 1 for now), shared kernel helpers (phase accumulator, one-pole, loop filter), `ssb_demod` built on `ddc`; a procedural macro that generates `Chain`/`Fork` compositions; a pipeline representation of composite blocks (`expand_composites`, group provenance, splitting a flow by groups); an adder for more than two inputs; fractional delay alignment; two clock domains in one pipeline (the `clock_domain` check of M34 rejects them); text parameters (`ParamKind::Text`; M42 sends PS/RT as packets); SigMF annotations for packets; packets above 256 bytes.
- **AFC on random data (from M39, D585):** an `afc` that follows a carrier drift without lag also on random data, for example a second-order loop (which may then average over a long time constant) or an update gated by the preamble; the first-order loop of M39 holds 50 Hz only on balanced signals.
- **Noise reduction and audio (from M33, M35, M36):** spectral noise reduction, a Q15 `auto_notch`, DSB with suppressed carrier, SSB by the phasing method, shaped CW keying, a speech compressor, CQ15 variants of `preemph_limit` stereo and `stereo_encode`, a composite clipper.
- **Real hardware:** the same `targets/` on boards via `probe-rs` (Cortex-M, ESP32 via `espflash`), DWT cycle counters / `mcycle`, real-time targets per platform (the plan defers them until hardware is in use).
- **Device API gaps** identified by the SoapySDR mapping in M12 (sensors, generic settings, frequency components, clock/time source selection).
- **Optional:** GStreamer-style shorthand for flows (`rf ! ddc frequency_hz=600e3 ! fm_demod ! out`) compiled to the JSON model; compiling a JSON flow into heap-free Rust code for MCUs.
- **Release work:** check that `sdrk` is free on crates.io and npm, crates.io publishing in the order given in CONTRIBUTING.md, npm package name.

## Later (prepared, not scheduled)

- Multi-threaded runner that sleeps when idle, using node groups (M11) as the partitioning unit; node groups on MCU cores.
- Data-parallel blocks for OFDM and channelizers (polyphase filter bank channelizer; the kernel `channelize`, lane streams and the kinds `channelize` and `channel_select` come with M45; blocks that process all lanes at once (lane-wise demodulators, squelch, a `lane_sum`), lane streams of `CQ15` and `f32`, a `lanes` output type and a synthesis filter bank stay here).
- Repetition in flow descriptions: definitions of parameterized sub-flows, or a `for_each` over a list of values, expanded flat before validation (motivating case: the eight identical channel chains of `pmr446_monitor`, M45).
- Network splits using the wire format (M11) over TCP/WebSocket; with it packets across a split (from M37, D587): a packet message in a version 2 of the wire format, and the rate of the stream an encoder makes from the packets carried with a cut edge by `split_by_groups`.
- Metrics and tracing of a running pipeline (per-node load, buffer fill over time) for applications.
- GPU groups (e.g. wgpu, VkFFT), first as an experiment in a separate repository. Lowest priority of the whole backlog.
