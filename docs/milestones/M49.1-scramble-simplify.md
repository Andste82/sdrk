# M49.1 — `scramble`: one product for `bits ≥ 3`, a faster block and fair reference rows

> Plan: [PLAN.md › Phase 10](../PLAN.md#phase-10--digital-modes) · Depends on: [M49](M49-scramble.md) · Next: [M50](M50-xcorr-fft.md)

> **Status: implemented** (2026-11-18, branch `m49-1-scramble-simplify`; written 2026-11-18 from a design discussion with the maintainer after M49 was merged). Revises the `bits ≥ 3` part of the kernel `scramble`; `bits ≤ 2` is unchanged.

## Goal

1. **`bits ≥ 3`: one table phasor and one product per sample.** The index `k` selects the phasor at the full angle `2π k / 2^b` directly from the `rotate` tables, and the input is multiplied by it with the `rotate` product. The split into quadrant and residue, the exact quadrant map and the `r = 0` selection are dropped for `bits ≥ 3`. `bits = 1` and `bits = 2` keep the exact sign and swap operations of the shared conventions §A (no product, lossless).
2. **The block `scramble` gets faster:** the PRBS indices are produced with less work per sample, so that the block cost is dominated by the kernel.
3. **Fair reference rows:** the `bits = 8` comparisons with the phasor lookup plus VOLK become fair again (same work) and gate again; a fair row for `bits = 1` is added (complex samples times a real `±1` sequence, the form of srsRAN's `srsran_scrambling_c`).

## Why

Maintainer decision of 2026-11-18 (it revises decision 1 of 2026-11-17 for `bits ≥ 3`):
- For `bits ≥ 3` every sample with `r ≠ 0` goes through a product and is not exact; the round trip loses up to 2 LSB in `CQ15` whatever is done for the samples with `r = 0`. The exact quadrant map buys exactness only for the samples that fall on a multiple of `π/2` (one in two at `bits = 3`, one in 64 at `bits = 8`), which no guarantee of the contract uses, and costs about one cycle per sample on AVX2 (the cost of the whole `bits = 2` kernel, M49 measurement).
- The scrambler sits in the sample path of DSSS and OFDM chains, so its speed matters. With one product, the kernel does the same work as the library composition (lookup, then complex product) in one pass, so the comparison is fair and SDRk must beat it.
- M49 measured the block `scramble_block` at about 11 simulated cycles per sample at `avx2` against about 2.5 for the kernel at `bits = 8`: the index production (PRBS bits into phase bytes) dominates, not the kernel.

## Order

M49.1 depends on M49 only. M50 and M51 do not depend on the `bits ≥ 3` part of `scramble` (M51 uses the binary chips of §A, which stay); they may run in parallel. The shared conventions §A are unchanged; §A.4 (how M49 uses §A) is updated to say that the quadrant split applies to `bits ≤ 2` only.

### R3 — `no_std` and no heap (applies to every crate marked "yes" above)

1. The crate root starts with `#![no_std]`. The crate never writes `extern crate alloc;` and never uses `Vec`, `Box`, `String`, `Rc`, `Arc`, `BTreeMap` or anything else that allocates. `cargo xtask bare-metal` builds these crates for `thumbv7em-none-eabihf`, which has no global allocator, so any accidental allocation fails the build.
2. Memory is provided by the caller. State types are generic over their storage: a field that holds samples has a type parameter `S: AsRef<[T]> + AsMut<[T]>` (read-only data: `S: AsRef<[T]>`). On a microcontroller the caller passes `[T; N]` or `&mut [T]`; in upper layers the caller may pass `Vec<T>`. Constructors validate lengths and return `Err`, never panic.
3. Fixed-capacity containers come from `heapless` when needed.
4. No function may keep more than 4 KiB on its stack (WASM and MCU stacks are small). Large buffers belong in caller-provided storage. `clippy.toml` sets `stack-size-threshold = 4096` and the workspace enables `clippy::large_stack_frames` and `clippy::large_stack_arrays` as errors.
5. Math functions come from `libm` (e.g. `libm::sinf`, `libm::atan2f`, `libm::log10f`), never from `f32::sin()` & co. This keeps code `no_std` **and** makes results identical on every platform because `libm` is pure Rust.
6. Upper layers (`pipeline`, `io`, `bindings`, `examples`, `xtask`, testkit feature `std`) may use `std` and allocate. The only `std` use allowed below the heap boundary besides the testkit's `std` feature is runtime CPU-feature detection in backend crates behind their `std` feature (M13); it never allocates. The pipeline allocates only while *building*; after `build()` returns, processing must not allocate (tested with a counting global allocator in M10).

### R4 — Clean interfaces

1. Each crate exposes a small, documented public API through `lib.rs` re-exports; everything else is `pub(crate)`. Module layout inside a crate is an implementation detail.
2. Public enums that may grow are `#[non_exhaustive]`. Public structs with invariants have private fields, a validating constructor (`new(...) -> Result<Self>`) and getters.
3. Kernels follow the **one trait per kernel** pattern defined in M02: the trait is generic over the sample type, `Fallback` (in `sdrk-core`) implements it for every supported sample type, `Reference` (feature `reference`) implements it as the f64/integer specification, backends implement only the variants they accelerate, and the facade type `sdrk::Sdrk` implements all of them by delegating to the chosen implementation.
4. Kernel calls never allocate, never block, never read a clock, never use randomness, and never print.
5. Every public item has a rustdoc comment; every public function with non-trivial behaviour has a doc example that compiles (`#![deny(missing_docs)]` in every library crate; `cargo test --doc` runs the examples).
6. All public types are `Send`; state types and blocks are also `Sync` unless they need interior mutability (they should not). Add compile-time assertions in each crate's tests: `fn _assert_send<T: Send>() {}` called for every public type.

### R5 — One error-handling scheme for the whole workspace

1. The lowest crate `sdrk-device` defines the shared classification:
   ```rust
   #[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
   #[non_exhaustive]
   pub enum ErrorKind {
       InvalidArgument, LengthMismatch, BufferTooSmall, OutOfRange, Unsupported,
       CapacityExceeded, InvalidState, ResourceLimit, Parse, Validation,
       Io, Device, Timeout, Disconnected, Internal,
   }
   pub trait SdrkError: core::error::Error {
       fn kind(&self) -> ErrorKind;
   }
   ```
2. Every library crate defines **its own** `pub enum Error` (`#[non_exhaustive]`, `Debug`, `Clone`, `PartialEq`) and `pub type Result<T, E = Error> = core::result::Result<T, E>;`. The enum implements `core::fmt::Display` (lowercase message, no trailing period), `core::error::Error` and `SdrkError`. Heap-free crates keep their error variants allocation-free (`&'static str` and integers only). Upper crates may carry `String` paths (e.g. `nodes.ddc.params.frequency_hz`).
3. Wrapping: an upper crate's error has a variant like `Core(sdrk_core::Error)` with `From` impls; `kind()` forwards to the inner error. `source()` returns the wrapped error.
4. **No panics in library code for any input that can reach a public API.** Every library crate root contains:
   `#![deny(clippy::unwrap_used, clippy::expect_used, clippy::panic, clippy::todo, clippy::unimplemented, clippy::indexing_slicing)]`
   Tests may opt out with `#[cfg_attr(test, allow(...))]` on the test module only. Validate lengths and parameters once at the public entry point; inner loops then iterate with `zip`, `chunks_exact`, `iter_mut` instead of indexing. Where indexing is unavoidable, use `.get()` and return `Error::Internal` if it ever fails.
5. Integer arithmetic that may overflow is written explicitly as `wrapping_*`, `saturating_*` or `checked_*`. The test profile keeps `overflow-checks = true`.

### R6 — Determinism and global state

1. No global mutable state: no `static mut`, no `static` with interior mutability (`Cell`, `RefCell`, `Mutex`, atomics, `OnceCell`, `LazyLock`), no `lazy_static`. Lookup tables are `const`/`static` immutable data, generated by `build.rs` where needed. `cargo xtask check` greps the source of library crates for these patterns and fails.
2. Same backend + same input = bit-identical output, independent of how the input is split into blocks. Every stateful kernel and block gets a block-size-invariance test (testkit helper from M03).
3. No reliance on CPU floating-point modes (flush-to-zero, rounding modes). Feedback states are flushed explicitly: `sdrk_core::num::flush_denormal(x)` returns 0.0 when `|x| < 1e-30`.
4. No hash-map iteration order in any output; use `BTreeMap` or ordered `Vec`s in upper layers.
5. Fused multiply-add is used only where the numeric contract allows it; the reference and the fallback never use FMA.
6. Little-endian only: `sdrk-device` contains `#[cfg(target_endian = "big")] compile_error!("sdrk supports little-endian targets only");`.

### R7 — Numeric conventions (from the plan's Decisions table)

| Topic | Rule |
| --- | --- |
| Q15 format | `Q15(i16)`, value = raw / 32768, range −1 … 1 − 2⁻¹⁵ |
| Rounding | round half up: add ½ LSB, then arithmetic right shift (`(x + (1 << (s - 1))) >> s` on a signed integer) |
| Overflow | always saturate to `[-32768, 32767]`, never wrap |
| Multiply | `sat16((a as i32 * b as i32 + (1 << 14)) >> 15)`; therefore `-1 × -1 = 32767` |
| Accumulation | reference and fallback accumulate Q30 products in `i64`, round and saturate once at the end; accelerated variants may use narrower accumulators if their headroom is documented |
| f32 → Q15 | computed in **f64**: `v = (x as f64) * 32768.0`; NaN → 0; otherwise `floor(v + 0.5)` clamped to `[-32768, 32767]` (so +1.0 → 32767, ±∞ → ±limit). Doing this in f32 would round twice and differ from the Python model |
| Q15 → f32 | `raw as f32 / 32768.0` (exact) |
| Complex Q15 | `CQ15 { re: Q15, im: Q15 }`, `#[repr(C)]`, I before Q — byte-identical to interleaved little-endian `cs16` |
| Denormals | flush feedback state to 0.0 below 1e-30 (R6.3) |
| Kernel classes | *bit-exact* kernels: fallback output equals the reference output bit for bit (Q15 and f32). *tolerance* kernels: output must reach the minimum SNR stated in the kernel's numeric contract (`docs/kernels.md`) against the f64 reference |

## Specification

### 1. Kernel, `bits ≥ 3`

- `k = p[n] & (2^b − 1)`; `inverse` replaces `k` by `(−k) & (2^b − 1)` (unchanged).
- Table index `i = k << (12 − b)` (0 to 4095 − 2^(12−b)); `c = COS[i]`, `s = COS[(i + 3072) & 4095]` (`COS_F32` or `COS_Q15`): exactly the entries that `rotate` reads for the phase `k << (32 − b)`, whose interpolation fraction is 0 (M49 §1 "direct lookup").
- `C32`: `y = (re·c − im·s, re·s + im·c)` in `f32` without FMA (the `rotate` `C32` product). `CQ15`: `sat16((xr·c − xi·s + 2^14) >> 15)`, `sat16((xr·s + xi·c + 2^14) >> 15)` in `i32` (the `rotate` `CQ15` product).
- **Relation to `rotate`:** for every `k` at `bits` 3 to 8 the output equals one `rotate` step at the constant phase `k << (32 − b)` bit for bit (a zero-increment `Nco` with `set_phase`). This is the property the first M49 draft had, now with a direct lookup.
- No quadrant map, no `r = 0` selection for `bits ≥ 3`. Consequences, documented in the contract: `k = 0` at `bits ≥ 3` multiplies by `(32767, 0)` in `CQ15` (scale `1 − 2⁻¹⁵`) and by `(1.0, s₀)` with the tiny `f32` sine of the table in `C32`; `±∞` may become NaN (`∞ · 0` or `∞ − ∞`), NaN by class (D296).
- `bits = 1, 2`: unchanged (exact quadrant map, bit for bit as in M49).
- **Reference:** for `bits ≥ 3`, `z = x · (cos θ, sin θ)` with `θ = 2π k / 2^b` from `libm::cos/sin` in `f64`, rounded once. Class tolerance.

### 2. Contract

| Kernel | Sample types | Class | Contract |
| --- | --- | --- | --- |
| `scramble` | `C32` | tolerance | `bits ≤ 2` as M49 (exact, bit-exact against the reference, `to_bits()` incl. NaN); `bits ≥ 3`: SNR ≥ 120 dB vs the f64 reference, the `rotate` product with the table phasor at `k << (12 − b)`, no FMA; fallback and every SIMD path equal bit for bit (NaN by class, D296) |
| `scramble` | `CQ15` | tolerance | `bits ≤ 2` as M49; `bits ≥ 3`: SNR ≥ 80 dB vs the f64 reference, the `rotate` `CQ15` product; fallback and every SIMD path equal bit for bit |

Round trip for `bits ≥ 3`: `C32` SNR ≥ 120 dB; `CQ15` the bound is measured by the unit test over every input pattern of M49 test 2 and every `k` and fixed in the test and in `docs/kernels.md` (expected 2 LSB per component for `|x| ≤ 1`; if the measurement gives more, the number is recorded as a decision, not hidden).

### 3. SIMD

Paths on every level (`sse2`, `sse4.2`, `avx2`, `avx512`, `neon`, `simd128`), bit-identical to the fallback, D321 gate. The per-sample `(c, s)` come from an in-register permute where the `2^b`-entry table of the call fits the registers of the level, otherwise from a gather or from per-sample pair loads; the form per level and `bits` is chosen by **simulated cycles** (`cargo measure`), and the AVX2 gather form (dropped in M49 on wall-clock timing only, D2070) is measured in cycles this time and recorded with its numbers. The product is that of M49 §5 (no FMA; `CQ15` `pmaddwd` form, no `pmulhrsw`/`vqrdmulh`). The table of the call may be built once per call (at most 256 entries).

### 4. Block `scramble`: index production

The phase indices stay those of M49 §6 (sample `n` takes the next `bits` PRBS bits, the first as the MSB of `p[n]`; the PRBS position runs on across calls). The block produces them with less work per sample: for example, whole PRBS words (`Prbs::next_bits`) split into `bits`-wide indices with byte or vector operations instead of a per-sample shift loop, and for `bits = 8` one byte per sample in MSB-first order. Any form is allowed if the indices equal those of the per-bit specification (`next_bit`), checked by a test over the full period of every polynomial and every `bits` 1 to 8, in 20 chunk plans. The target: the `scramble_block` cycles per sample approach those of the kernel; the result is recorded in `docs/performance.md` with the share of the index production.

### 5. Reference rows

| Our entry | Library row | Marking |
| --- | --- | --- |
| `scramble_c32_b8` and `scramble_c32_b8_fallback` | the phasor lookup into a buffer + VOLK `volk_32fc_x2_multiply_32fc` (as in M49) | **fair** again (same work in one pass instead of two): status `release`, gated; D2092 is revised for these rows |
| `scramble_cq15_b8` and `scramble_cq15_b8_fallback` | the lookup + CMSIS-DSP `arm_cmplx_mult_cmplx_q15` | stays "reference does less work" (CMSIS truncates and writes Q3.13, SDRk rounds and saturates; D2092) |
| new `scramble_c32_b1` and `scramble_c32_b1_fallback` (`bits = 1`) | a `±1.0` `f32` sequence from the same index bits + VOLK `volk_32fc_32f_multiply_32fc` (the form of srsRAN's `srsran_scrambling_c`, which calls `srsran_vec_prod_cfc` with a real `±1` sequence) | fair (same task: sign scrambling of complex samples) |

The new entries get count and cycle entries like the M49 entries (`cargo xtask count`, `cargo measure`, every level with a core model; instruction counts only for `simd128`). A gap of more than 10 % against a fair row after attempts to close it is an open item with its numbers.

### 6. Pipeline cost

`docs/pipeline.md`: the cost of the kind `scramble` is measured again for `bits ≥ 3` and for the faster block, relative to `rotate` (6).
