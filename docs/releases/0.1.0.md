# SDRk 0.1.0

SDRk (Software-Defined Radio Kernels) is a Rust library of SDR building blocks for receiving and transmitting: kernels from mixers and filters to demodulators, blocks built on them, and JSON pipelines that compose the blocks and are controllable at runtime. The kernels and blocks are `no_std` and heap-free, so the same code runs on microcontrollers, on desktop CPUs with SIMD and in the browser. 0.1.0 is the state before the block interface changes in M26; it is released as the git tag `v0.1.0` and is not published to crates.io or npm.

## What 0.1.0 contains

- **Kernels** (`sdrk-core`): one trait per kernel with a scalar fallback, an f64/integer reference and golden vectors, `f32`/`C32` and `Q15`/`CQ15` types; see [kernels.md](../kernels.md).
- **SIMD backend** (`sdrk-backend-simd`): SSE2, SSE4.2, AVX2 and AVX-512 on x86-64 (fixed or detected at run time), NEON on AArch64, SIMD128 on wasm32; see [backends.md](../backends.md) and [performance.md](../performance.md).
- **Blocks** (`sdrk-blocks`): 20 block kinds under one naming scheme (M24.1), with caller-provided storage; see [blocks.md](../blocks.md).
- **Pipeline** (`sdrk-pipeline`): JSON and YAML flow descriptions with validation, a JSON Schema, time and events, push and pull mode, groups; see [pipeline.md](../pipeline.md) and [timing.md](../timing.md).
- **I/O and devices** (`sdrk-io`, `sdrk-device`): raw sample formats, WAV files, the wire format and the device capabilities; see [io.md](../io.md), [wire-format.md](../wire-format.md) and [device.md](../device.md).
- **WebAssembly** (`bindings/wasm`): the engine with the npm package layout (scalar, SIMD128 and relaxed SIMD modules); see [wasm.md](../wasm.md).
- **Emulator targets**: the testkit suite bare-metal on Cortex-M4F, Cortex-M55 and RISC-V `rv32imac` (ESP32-P4 and ESP32-S3 build and run locally; CI has paused them, D201); see [embedded.md](../embedded.md).
- **Receive and transmit flows** (`examples/flows`): FM broadcast (mono, stereo, a real-sampling input), NFM, AM, airband, SSB, a spectrum view, audio resampling, and the FM and NFM transmitters with pre-emphasis and limiter.

## Platforms and SIMD levels

Host platforms: Linux x86-64, Linux arm64 and Windows x86-64 (build, tests, `xtask`, the golden generator). SIMD levels: `sse2`, `sse4.2`, `avx2`, `avx512` and the run-time dispatch on x86-64, `neon` on AArch64, `simd128` (and relaxed SIMD) on wasm32; every kernel also runs on the scalar fallback. Bare metal: `thumbv7em-none-eabihf` (Cortex-M4F), `thumbv8m.main-none-eabihf` (Cortex-M55), `riscv32imac-unknown-none-elf`.

## Known limits

Open items of [open-items.md](../open-items.md), one line each:

- M10: a stream output with a raw `format` works only for complex streams.
- M13-5: the nightly count jobs of `x86_64-avx512`, `aarch64` and `wasm32` have not passed yet.
- M13-6: `cargo xtask count` on a Linux arm64 host measures the AArch64 level through QEMU only.
- M13-7: the cargo feature `std` of the facade is not forwarded by `sdrk-blocks`.
- M13-10: maintainer decisions left open by the SIMD optimization.
- M14-1: the npm package is not published.
- M15-2: `xtask emu` is untested on Linux arm64 and Windows x86-64.
- M15-3: the `hardware` build of the ESP32-S3 target has never run on a board.
- M15-4: the ESP emulators are pinned binaries whose long-term availability is not assured.
- I20-1: the `Q15`/`CQ15` FIR family fallbacks are above CMSIS-DSP in simulated cycles at `sse2`, `sse4.2` and `neon`.
- I23-1: the `CQ15` `real_to_complex` entries are `info` against libairspy until a maintainer decision.
- I23-2: the `f32`/`C32` halfband fallback adds the centre tap last.
- I23-3: the work-saving evidence of `halfband_decimate` against `fir_decimate` by 2 is information.
- I24-1: `stereo_pll_fallback` misses its limit against liquid-dsp at five levels (waived).
- I24-2: on pure noise the stereo lock detector can switch to stereo within 1 s.
- I24-3: `stereo_matrix_fallback` misses its limit against CMSIS-DSP at `sse2` (waived).
- I25-3: host-dependent counts of one M24 reference and the verdict of `stereo_pll_fallback`.

Issue [#71](https://github.com/Andste82/sdrk/issues/71) collects the speed-against-accuracy decisions (the rounding of `convert_out` CU8, a polynomial `power_db`, the `CQ15` FFT contracts, the CMSIS-DSP references on AArch64) and the cycle gaps of the fallbacks.

Accepted waivers (`cargo xtask release-check 0.1.0` lists every `dev` or `release` entry with a waiver):

- The reference does other or less work: `agc_fallback` at `sse2`, `sse4.2` and `neon`; `convert_cq15_cu8_fallback` on `neon`.
- The reference computes in another accuracy class: the `accuracy_waiver` of `fir_decimate_fallback` and `deemphasis_fallback` at every level.
- The run-time build keeps the SIMD branch: `fir_cq15`, `fir_interpolate_cq15` and `fir_interpolate_real_q15` at `avx2-runtime`.

## What changes next

From M26 on the block interface changes (block ports, `Chain`, clock drift, primitive and two-port blocks); 0.1.0 is the state to pin before that. See the [milestones](../milestones/README.md).

## How to pin

Nothing is on crates.io: depend on the tag, for example `sdrk = { git = "https://github.com/Andste82/sdrk", tag = "v0.1.0" }`.
