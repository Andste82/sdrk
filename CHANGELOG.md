### Added

The state update is `s1 = (b1 x + s2) - a1 y` (before `(b1 x - a1 y) + s2`), the association of KFR and CMSIS-DSP, 1.6 to 2.4 dB more accurate on the Butterworth cases; the golden case `retune_f32_8192` is regenerated. The facade delegates `biquad_real` to the SIMD backend (`backend_for` reports `simd`).
- The SIMD backend no longer supports 32-bit x86 (`target_arch = "x86"`): its level paths are compiled for x86-64 only, the facade builds the backend only on x86-64, AArch64 and wasm32 and uses `Fallback` on 32-bit x86, and CI no longer tests `i686-unknown-linux-gnu`.
- CI is three workflow files: `tree.yml` holds the jobs as a tree (`check` gates one build per platform, the tests of each platform use its build through `cargo nextest archive`), `ci.yml` runs it for pull requests (a push to `main` runs `smoke` only) and `nightly.yml` every night with the long jobs (sweeps, emulators with the full profile, every count, fuzzing, the long run; the ESP32-P4 full profile on Sunday). New: `check_msrv` (Rust 1.89), the golden generator on Windows and arm64 (it must run there; the vectors are generated on Linux x86-64, the byte comparison is information), clippy for wasm32-wasip1 with SIMD128 and for thumbv7em, the level check `neon` on the native arm64 runner, an issue when a nightly run fails. Gone: `aarch64-qemu` (AArch64 runs natively), the x86-64 SIMD variants on Windows (R1.3 now runs architecture-only variants once per architecture) and the workspace run with `-C target-cpu=x86-64-v3`.
- M13: the minimum Rust version of the workspace is 1.89 (the MSRV of `fearless_simd`). With the default feature `simd` of the facade, the `C32` kernels `rotate`, `fir`, `fir_decimate`, `fir_interpolate`, `resample`, `quad_demod` and `fft` and the `f32` kernels `rfft` and `irfft` give results that meet their SNR contract but are no longer bit-identical with `Fallback` (the bit-exact kernels and the `CQ15` kernels except `quad_demod` and `fft` still are); `RUSTFLAGS="--cfg sdrk_fallback_only"` restores the fallback everywhere. `sdrk-pipeline` turns on run-time level detection (`sdrk/std`). A backend preference `{"require": "simd"}` now succeeds for nodes whose kernels are accelerated.
- M14: `C32` `mag_sq` was documented as not bit-exact in the relaxed WebAssembly build (feature `relaxed-simd` with `+relaxed-simd`). The relaxed multiply-add was never used there: `C32` `mag_sq` is bit-exact with the fallback in every build (M13 SIMD optimization), and the tests check it bit for bit again.
- `convert_out` from `C32`/`f32` in the fallback takes an integer path on bare-metal 32-bit Arm and RISC-V for the formats without offset with a power-of-two full scale up to 2^21 (all built-in formats except `CU8`, `CF32` and `I2S32_MSB`): about 150 instead of 1320 QEMU instructions per `CS16` sample on Cortex-M4F, Cortex-M55 and RV32IMAC. The output is unchanged (checked for every f32); other targets keep the `f64` formula.
- M13 (SIMD optimization): `convert_out` rounds half to even (`C32`/`f32` and the Q15 integer rules, decision D7; golden vectors `convert_out/*` regenerated at the ties). For `U8` every amplitude that is a multiple of `1 / full_scale` is now a tie (0.0 and 1/128 both give 128); decode-then-encode round trips stay exact.
- M13 (SIMD optimization): `sdrk-backend-simd` may contain level-specific `core::arch` code with small `unsafe` helpers (decision D1), each path with the generic code as its fallback and a test against it. New paths for `convert`, `convert_out`, `rotate`, `fir`, `fir_decimate`, `mag_sq`, `quad_demod`, `fm_mod` and both FFTs.
- M13 (SIMD optimization): the `C32` FFT of the backend uses radix-4 passes (radix-8 on NEON and wasm32) with static per-span twiddle tables; debug builds of downstream crates no longer overflow the stack in the `C32` FFT. The `CQ15` FFT of the backend is a radix-4 transform in `i16` lanes within the SNR contract (decision D10) and is no longer bit-identical with the fallback (its block-floating-point exponent may differ); the fallback and the golden vectors are unchanged.
- M13 (SIMD optimization): `convert_out` to `CU8`, `CS8` and `CS16` needs fewer instructions at SSE2, AVX2 and NEON (`CU8` with one byte bound per value instead of `floor(y)`, aligned SSE2 loads after a scalar head); `rotate` `CQ15` and the sized `C32` FFTs cost less per call under run-time detection (`level::dispatch_fn!` passes the arguments in registers and tests AVX2 first); the `C32` FFT has lower fixed and per-pass costs on every level (for example `avx2` 6.28 to 5.84 instructions per sample at N = 64, `neon` 11.27 to 10.52, wasm32 39.1 to 35.5).
- M13 (SIMD optimization): `fir` and `fir_decimate` `C32` of the backend use FMA on AVX2, AVX-512 and NEON (decision D5) and their own order of summation; `rotate` `C32` of the backend is a block oscillator whose output depends on `(phase_n, inc)` (decision D8, `docs/timing.md`); `quad_demod` `C32` uses an f32 `atan2` on every level.
- M13 (SIMD optimization): `sdrk-backend-simd` gets the features `fft-tables` (41 KiB) and `nco-tables` (96 KiB) of static tables. The facade `sdrk` gets the features `fft-tables` = `sdrk-backend-simd?/fft-tables` and `nco-tables` = `sdrk-backend-simd?/nco-tables`; it enables `fft-tables` by default on x86-64 and AArch64 and `nco-tables` on x86, x86-64 and AArch64 through target-specific dependencies (decision D13).
