# Kernels

How kernels are structured in SDRk, and the numeric contract of each one.

## The one-trait-per-kernel pattern

For every kernel `foo` there is:

1. A trait in `sdrk_core::kernels::<category>`, generic over the sample type:
   `trait Foo<T: Sample> { fn foo(&self, [state,] input: &[T], output: &mut [T], [params]) -> Result<()>; }`.
   Rust has no stable specialization, so the trait itself carries the sample type.
   - Same-rate kernels require `output.len() == input.len()`, otherwise `Error::LengthMismatch { expected: input.len(), got: output.len() }`.
   - Rate-changing kernels return `Result<Progress>`; they consume as much input as possible and produce at most `output.len()` samples. Unconsumed input is resubmitted by the caller.
   - Stateful kernels take `state: &mut FooState<..>` right after `&self`.
2. `Fallback` (`sdrk_core::Fallback`): the portable, optimised-scalar implementation for every supported sample type.
3. `Reference` (`sdrk_core::Reference`, feature `reference`): the executable specification, f64 for f32 kernels and the exact integer model for Q15 kernels. Clarity over speed.
4. The facade `sdrk::Sdrk` implements the trait for every sample type by delegation, written with `sdrk::delegate!`:

   ```rust,ignore
   delegate!(Scale<C32>::scale(&self, input: &[C32], output: &mut [C32], gain: f32) -> Result<()> => Fallback);
   ```

   A backend changes only the `=> Backend` target (guarded by `#[cfg(..)]`). The same entries build the table behind `sdrk::backend_for(kernel, sample_type)`, which returns the implementation name or `"none"`.
5. A row in the contract table below.

`sdrk_core::map_kernel!` generates the body of a same-rate, stateless, per-sample fallback: it checks the lengths and applies a closure to every sample. It is the starting point for later SIMD "process one" helpers.

## Numeric contract

Classes: *bit-exact* (fallback equals the reference bit for bit) and *tolerance* (minimum SNR against the f64 reference). One exception to the f64 reference rule: a kernel whose output depends on a discrete decision (`squelch`) fixes its arithmetic in the specification, the reference follows it exactly and the golden cases come from an exact float32 model (see `squelch` below). Q15 rules: round half up, saturate, `-1 * -1 = 32767` (except the encoding rules of `convert_out`, which round half to even, see there).

### `convert` and `convert_real`

`Convert<T>::convert(&format, input_bytes, output) -> Result<usize>` decodes whole samples and returns their number; `ConvertReal<T>` does the same for `Layout::Real`. The effective integer value `e` of each component follows `docs/device.md` (byte order, alignment, sign extension, packing, I/Q swap, planar halves). Errors: a trailing partial sample or packing group gives `InvalidParameter("partial sample")`, an output shorter than `format.samples_in_bytes(input.len())` gives `BufferTooSmall`, `Bits1` gives `Unsupported`, a layout that does not match the trait gives `InvalidParameter`. A longer output is allowed; only the decoded prefix is written.

- **To `f32`/`C32`:** `(e - offset) / full_scale` in f32 with `offset = 127.5` for `U8` and 0 otherwise. For at most 24 effective bits (and an explicit full scale up to 2^24) every operation is exact or a single correctly rounded division. Beyond that (`I32` with more than 24 bits) the value is computed in f64 and rounded once to f32. `F32` containers are copied (byte-swapped when big-endian); NaN, infinities and -0.0 pass through unchanged.
- **To `Q15`/`CQ15`:** `U8`: `q = (2u - 255) << (15 - bits)`, i.e. `(u - 127.5) * 256` for 8 bits; signed power-of-two full scale with at most 16 bits: `q = e << (16 - bits)`; more than 16 bits: `sat16(round_shift(e, bits - 16))`; explicit full scale `n`: `sat16(floor((e * 65536 + n) / (2n)))` (`U8` uses `(2u - 255)` instead of `2e` and `32768` instead of `65536`), which is round half up of `e * 32768 / n`; `F32`: `q15_from_f32` (NaN gives 0, infinities saturate).
- **Packed containers** ignore `align` and `endian` (they are LSB-first bit streams); `Msb` alignment applies to `U8`, `I8`, `I16` and `I32`.

`view_cq15` and `view_c32` return a zero-copy view when the bytes already have the layout of the internal type (little-endian, interleaved, no I/Q swap, power-of-two full scale for `CS16`) and are aligned and whole; the view equals what `convert` would write, bit for bit. Empty input gives an empty view.

### `rotate`

`Rotate<T>::rotate(&mut Nco, input, output)` multiplies by `exp(j 2 pi phase_n / 2^32)`; the phase model is in `docs/timing.md`. The tables are generated by `crates/core/sdrk-core/build.rs` (build dependency `libm`): `COS_F32[k] = cos(2 pi k / 4096)` as f32 and `COS_Q15[k]` the same f64 value rounded by the Q15 rule, `k = 0..=4096`. Sine is cosine at `phase - 2^30`. Both tables are plain immutable data.

- **Fallback `C32`:** `idx = phase >> 20`, `f = (phase & 0xFFFFF) / 2^20` in f32, `c = a + (b - a) * f` (no FMA), result `(re c - im s, re s + im c)`.
- **Fallback `CQ15`:** `f15 = (phase >> 5) & 0x7FFF`, `c = sat16(a + round_shift((b - a) * f15, 15))` in `i64`, then `cq15_mul`.
- **Reference:** `theta = 2 pi phase / 2^32` in f64, `libm::cos/sin`, f64 complex product, rounded once.
- **SIMD backend `C32`:** a block oscillator instead of the table (see [backends.md](backends.md)); an output sample is a function of `(phase_n, inc)` and the input sample, so it does not depend on the split into calls, but after a retune its bits can depend on the increment as well as on the phase (decision D8, [timing.md](timing.md#block-size-invariance)). Contract: SNR >= 120 dB as above.
- The table value at angle 0 is `32767/32768` (not 1.0), so `CQ15` rotation by zero is the identity only for `|x| <= 16384` and within one LSB for larger values. In `C32` the sine of angle 0 is the table entry for 3 pi / 2 (about -1.8e-16), so rotation by zero is exact whenever `|im| * 1.8e-16` is below half an ULP of `re` (always true for ordinary signals; an input with `re = 0` and `im != 0` receives a residue of about 1e-16).
- A rotated `CQ15` sample whose magnitude exceeds 1 saturates one component; the golden cases clip their expected value the same way.

### `fir`

`FirState<T, Taps, Hist>` owns real taps (`T::Real`, so `f32` for `C32` and `Q15` for `CQ15`) and a history of the last `taps.len() - 1` samples (oldest first), both in caller-provided storage (`[T; N]`, `&mut [T]`, `Vec<T>`). `FirState::new` rejects empty taps (`InvalidParameter`) and a history of the wrong length (`LengthMismatch`) and zeroes the history; `reset()` clears it. `Fir<T>::fir` computes `y[n] = sum h[k] x[n - k]` with samples before the start taken from the history and updates the history to the last `N - 1` samples of (old history ++ input). A call with empty slices changes nothing; unequal lengths give `LengthMismatch` and leave the state untouched.

- **`C32` fallback:** separate f32 accumulators for `re` and `im`, starting at 0.0, `k` ascending, no FMA. The order is fixed so the result does not depend on the block size.
- **`CQ15` fallback and reference:** `Acc64` per component, `sat16(round_shift(acc, 15))` once. Bit-exact.
- **`C32` reference:** f64 accumulation, one cast to f32.

### `fir_decimate`

`FirDecimState<T, Taps, Hist>` holds the real taps, a history of `N - 1` samples, the factor `M >= 1` (`new(taps, history, factor)`, `reset()`, getters `factor()`, `taps()`, `history()`, `countdown()`) and a countdown of input samples to skip. With `y_full[n] = sum h[k] x[n-k]` over the whole stream (zero history at the start and after `reset`) the outputs are `y[m] = y_full[m * M]`: the first input sample after a reset produces the first output, and the `m`-th output follows `M` input samples after the previous one. The fallback computes only the outputs it emits. `fir_decimate` returns `Progress`: an input sample that would produce an output is not consumed when the output buffer is full, so `consumed` stops right before it; samples that produce nothing are consumed up to that point. The caller resubmits `input[consumed..]`. The accumulation is the one of `fir`, so `M = 1` equals `fir` bit for bit. Timing: ratio `1/M`, group delay `Delay::new(N - 1, 2)` in input samples.

### `resample` and `resample_real`

`ResampleState<T, Taps, Hist>` (complex signals, `ResampleRealState` for `f32`/`Q15` signals) holds the taps `h` designed at the upsampled rate (the interpolation gain `L` is part of the taps, the caller includes it), `up = L >= 1`, `down = M >= 1`, a history of `ceil(N / L)` input samples (`new` checks the length, `LengthMismatch` otherwise) and the output phase. The definition is `scipy.signal.upfirdn(h, x, up=L, down=M)` restricted to the outputs that depend only on received input: `y[j] = sum_k h[k] u[j M - k]` with `u[i] = x[i / L]` when `i mod L == 0` and 0 otherwise. Output `j` is produced as soon as input sample `floor(j M / L)` has been received; evaluated as a polyphase filter with `t = j M`, `p = t mod L`, `b = t div L`: `y[j] = sum_{i >= 0, p + i L < N} h[p + i L] x[b - i]` with zeros before the first sample.

The number of outputs for `n` input samples after a reset is `K = floor((n L - 1) / M) + 1` (check: `L = 3`, `M = 2`, `n = 1` gives `K = 2`). The state keeps the output phase as `q = j M - L c` (`j` outputs produced, `c` input samples consumed): an output is ready while `q < 0`, which is when `q` lies in `[-L, -1]` and the polyphase branch is `p = q + L`; a producing step adds `M`, a consuming step subtracts `L`. A sample is consumed only while no output is pending, so the newest sample is always the one the next output refers to and the history of `ceil(N / L)` samples suffices. The phase stays bounded however long the stream runs. `Progress` semantics are those of `fir_decimate`. Timing: ratio `L / M`, group delay `Delay::new(N - 1, 2 L)` in input samples. With `L = M = 1` the resampler equals `fir`.

The Q15 variants cannot hold a tap gain of `L` above 1; the golden case `resample/l3m2_n96_cq15_6000` therefore scales the taps by `1/3` (a documented gain loss of 3 that the caller restores after the resampler).

### `quad_demod`

`QuadDemodState<T>` keeps the previous sample (zero after `new`/`reset`). `output[n] = gain * arg(x[n] * conj(x[n-1]))` with `arg(0) = 0`; the first output after a reset is therefore 0. `C32`: the product in f32 without FMA, `libm::atan2f(im, re) * gain`, radians times the gain. `CQ15`: the product in exact `i64` (`re = ar*br + ai*bi`, `im = ai*br - ar*bi` with `a = x[n]`, `b = x[n-1]`), `phi = libm::atan2(im, re) / pi` in f64 rounded by the Q15 rule (unit: phase / pi, so a half turn is 32767), then `q15_mul(phi, gain)`; an accelerated variant may use CORDIC later. The reference does everything in f64 with a single rounding at the end; the Q15 fallback may differ from it by one LSB because it rounds twice. A typical gain for FM is `fs / (2 pi deviation)` (f32) so that full deviation maps to +-1. Timing: ratio `1/1`, group delay `Delay::new(1, 2)`.

### `deemphasis`

`DeemphasisState<T>::new(tau_s, rate)` computes `alpha = 1 - exp(-1 / (fs * tau))` in f64 and rounds it to the sample type (cast for `f32`, the Q15 rule for `Q15`); `tau_s` must be finite and positive. `f32`: `y = y + alpha * (x - y)` without FMA, then `flush_denormal`. `Q15`: `d = x - y` in `i64`, `y = sat16(y + round_shift(alpha * d, 15))`. After `tau * fs` samples the step response reaches 63.2 percent (within one sample). The filter is an IIR filter, so its delay depends on the frequency; `group_delay` reports 0 and the delay is not part of exact event timing. A NaN or infinite `f32` input poisons the state until `reset()` (a finite state is guaranteed only for finite input).

### `dc_block`

`DcBlockState<T>::new(r)` with `0 < r < 1` (Q15: raw 1 to 32767) holds `r`, the previous input and the previous output. Per component `y[n] = x[n] - x[n-1] + r * y[n-1]`. `f32`: as written without FMA; the stored `y_prev` is flushed with `flush_denormal`, the returned sample is not. `Q15`: `y = sat16((x - x_prev) + round_shift(r * y_prev, 15))`. **Limit of the Q15 variant:** the round-half-up feedback has a dead band, so a constant input does not decay to exactly zero but settles within `floor(0.5 / (1 - r_q15))` LSB per component; for `r_q15 = 32735` (0.999) that is 496 LSB (magnitude below 0.022). The `f32` variant removes a constant to below 1e-3 within 10 000 samples at `r = 0.999`. Timing: ratio `1/1`, group delay 0.

### `dc_block_real`

`DcBlockRealState<T: RealSample>::new(r)` is the real variant of `dc_block` with the same rules: `0 < r < 1` (Q15: raw 1 to 32767; anything else, NaN included, gives `InvalidParameter`), `y[n] = x[n] - x[n-1] + r * y[n-1]`, `f32` with `flush_denormal` of the stored `y_prev`, `Q15` `y = sat16((x - x_prev) + round_shift(r * y_prev, 15))`. The Q15 dead band of `dc_block` applies unchanged. Timing: ratio `1/1`, group delay 0. Not accelerated (first-order recursion).

### `mag`

`Mag<T>::mag(input, output)` writes the magnitude of complex samples (`C32` to `f32`, `CQ15` to `Q15`). `C32`: `libm::sqrtf(re * re + im * im)` without FMA; components above about `1.8e19` overflow the square to `+inf`, NaN gives NaN. `CQ15`: `s = re^2 + im^2` of the raw values in `i64` (at most `2^31`), `r = isqrt_u64(s)` (the exact floor of the square root), `y = r + (s - r^2 > r ? 1 : 0)` (the root rounded to the nearest integer; a tie is impossible for integers), output `sat16(y)`; the full-scale corners (`|x| > 1`) saturate, as in `mag_sq`. `sdrk_core::num::isqrt_u64(x)` is the exact floor of the square root of any `u64` (an f64 estimate corrected with `u128` products). The reference uses `sqrt` in f64 for `C32` and a bisection on `y * (y + 1) >= s` for `CQ15`.

### `agc`

`AgcState<T>::new(reference, attack_s, release_s, min_gain_db, max_gain_db, initial_gain_db, rate)` creates an automatic gain control for `C32` or `CQ15`. `reference` is the output amplitude `|y|` the loop settles at (linear, `2^-5` to `1`), the gains are in dB with `-40 <= min <= initial <= max <= 90`. The per-sample rates `r_a = 1 - exp(-1 / (fs * attack_s))` and `r_r = 1 - exp(-1 / (fs * release_s))` are computed in f64 and must lie in `(0, 0.5]` (a time constant of at least `1 / (fs * ln 2)`, 1.45 samples); every violation, also NaN and infinity, gives `InvalidParameter` (the specification says `OutOfRange`, which `sdrk_core::Error` does not have; all range errors of the kernels are `InvalidParameter` with kind `InvalidArgument`). `set_params(reference, attack_s, release_s, min_gain_db, max_gain_db, rate)` validates like `new`, changes everything but the initial gain (nothing on error), keeps the current gain and clamps it to the new range. `gain_db()` reads the gain (`20 * log10(g)`), `reset()` returns to the initial gain clamped to the current range.

The error is normalised by the OUTPUT level, as in the `agc3_cc` of GNU Radio (`gain = gain * (1 - rate) + ref * rate / |x|`, the only multiplicative AGC of GNU Radio): with `m = |y|`, `e = reference - m` and `r = r_a` (attack, `e < 0`, the output is too loud) or `r = r_r` (release, `e >= 0`) the gain is updated as

- attack: `g = g * d / (d + r_a * (m - reference))` with `d = min(m, 1.5 * reference)`;
- release: `g = g * (d + r_r * e) / d` with `d = max(m, reference / 4)`.

For `reference / 4 <= m <= 1.5 * reference` this is `g * (1 + r * e / m)`: with `u = m / reference` the output approaches the set point by `u' = u + r_r (1 - u)` on release and `u' = u - r_a (u - 1)` on attack, i.e. exponentially with the time constant `1 / r` samples at ANY level in that range, independent of the input level. Outside the range the divisor is limited: on release a signal more than 12 dB below the set point raises the gain by at most `1 + 4 r_r` per sample (`d = reference / 4`; a divisor `m` would let the gain jump to the maximum for an envelope near zero), on attack a signal more than 3.5 dB above the set point is corrected by a factor `1 / (1 + r_a (u - 1) / 1.5)` per sample (faster than exponential, bounded away from 0 and 1; a `CQ15` output that clips at full scale shows a level of at most 2.83 times a reference of 0.5, and the larger force there keeps the step up of 30 dB within 1 dB after 5 attack time constants). The attack form is divisive, so the factor of the update stays in `(0, 1)` for any overshoot and any allowed rate; the earlier form `g * (1 - r_a (u - 1))` became zero, and the gain collapsed to the minimum, as soon as `r_a (u - 1) >= 1`. A step of 30 dB settles within 1 dB after 5 time constants in both directions (measured with the 30 dB step down 0.08 dB and the step up 0.22 dB after 5 time constants), where the logistic update `g * (1 + (r / reference) * e)` needed 5.5 release time constants. The input sample of exactly zero (silence, the output of a closed squelch) carries no information and the gain is held; without this rule the gain would run to its maximum in every pause and the next transmission would start with it (the squelch and the AGC are used together in `airband_receiver`). With the specified AM time constants (attack 0.1 s, release 0.5 s) the audio level of an AM carrier with the modulation index 0.5 settles 0.98 dB below the level at which the mean envelope equals the reference (the overshoot is weighed more than the undershoot; every AGC with separate rates has such a bias, the logistic update 1.84 dB), see M20-2 in [decisions-log.md](decisions-log.md). Per sample, in this order:

- `C32`: the constants `ref`, `lo = ref / 4`, `hi = 1.5 ref` (each product rounded in f32), `r_a`, `r_r`, `g`, `g_min = 10^(min/20)`, `g_max = 10^(max/20)` are cast from f64 to f32; `c = r_r ref` and `b = r_r / lo` are computed in f64 from the f64 values of these f32 constants and rounded once to f32. `y = (g * x.re, g * x.im)` (written to the output); `a = sqrtf(x.re * x.re + x.im * x.im)` (the magnitude of the input) and `m = g * a` (the output level, `|y|` with other roundings). If `m > ref`: `d = min(m, hi)`, `g = min(max(g * d / (d + r_a * (m - ref)), g_min), g_max)`; else if `m >= lo`: `g = min(max(g + (c / a - r_r * g), g_min), g_max)`; else if `m > 0`: `g = min(g + g * (b * (ref - m)), g_max)`; otherwise (`m` zero or NaN) the gain is not updated. The two release forms are the release above rearranged, the same function with other roundings: for `d = m`, `g (m + r_r e) / m = g + r_r ref / a - r_r g` because `g / m = 1 / a` (no division by the output level, and `a` does not depend on the gain, so a backend computes it outside the recursion); for `d = lo`, `g (lo + r_r e) / lo = g + g (r_r / lo) e`. Both add the update to `g` last, so the rate keeps its full precision (a constant `1 - r_r` rounded to f32 shifts the effective rate by up to `2^-25 / r_r` relative, which lost about 20 dB of SNR when tried). The gain is clamped to `[g_min, g_max]` as specified: the attack lowers the gain and the release raises it, but near `m = ref` the attack and the first release form can miss the old gain by one rounding (up or down), so both clamp on both sides; the second release form adds `g` times a product of non-negative factors to `g` and never lowers it, so its clamp to `g_min` is left out (it would change no value). The test `c32_gain_at_a_limit_stays_there_exactly` holds a gain at each limit exactly in the two cases that a search found. All f32 without FMA, one division per sample. `m` is zero where `x.re^2 + x.im^2` is zero in f32: for an input of zero, and below about `|x| = 2^-75`, where the squares underflow (`g >= 0.01`, so `g * a` never underflows). The fallback runs four samples per iteration. The SIMD backend computes `a` and the products `y` in vectors per block of 256 samples and runs the same recursion in between (`AgcState::<C32>::gains_with`, which leaves out the last test in a block without a zero or NaN magnitude), so its values are those of the fallback bit for bit ([backends.md](backends.md)). The square root is `sdrk_core::num::sqrt_f32` (the `simd128` instruction on wasm32, where `libm` has only software code). An infinite input drives `g` to `g_min`; NaN reaches the output and leaves the gain alone. `Reference` runs the algorithm with the formulas of the specification (`m = |y|`, one divisor `d` per branch) in f64 with the f64 values of the f32 constants and keeps its f64 gain in the state between calls (the fallback leaves that field alone and refreshes it from its f32 gain after every call); the golden model does the same, so the rearranged forms change neither of them.
- `CQ15`: the gain `g` is an `i64` in Q.32 (value = raw / `2^32`, at most `31 623 * 2^32 < 2^47`). `ref_raw = floor(reference * 32768 + 0.5)` (at least 1024), `lo = ref_raw >> 2`, `hi = ref_raw + (ref_raw >> 1)`, the rates `r_raw = floor(r * 2^48 + 0.5)` (at most `2^47`), the limits `floor(10^(db/20) * 2^32 + 0.5)`. `y.c = sat16(round_shift(x.c * g, 32))` per component; an input sample of exactly zero (both raw components 0) holds the gain; otherwise `s = y.re^2 + y.im^2`; `m` is the rounded square root of `mag` **without** saturation (at most 46 341); `e = ref_raw - m`; for `e < 0`: `d = min(m, hi)`, `den = d * 2^48 - r_a_raw * e` and `g' = floor((2 g d 2^48 + den) / (2 den))` (the quotient `g d 2^48 / den` rounded half up); otherwise `d = max(m, lo)` and `g' = g + floor((2 g r_r_raw e + d 2^48) / (2 d 2^48))`; all in `i128` (every intermediate is below `2^112`); `g = clamp(g', g_min, g_max)`. Bit-exact between `Fallback` and `Reference`; the fallback computes the same values without integer division: the release as `floor((g r_r_raw e + d 2^47) / (d 2^48))` and the attack as `floor((g d 2^48 + floor(den / 2)) / den)` (`den < 0.854 * 2^64`), each from an f64 estimate `k` of the quotient plus `1/2` and one correction (`k - 1` when the remainder `n - k * divisor`, exact as the wrapping difference of the low 64 bits because the bounds keep it below `2^63` in magnitude, is negative), and `m` as the nearest integer to the f64 square root of `s` (exact for `s <= 2^32`). The bound arguments are in the comments of `crates/core/sdrk-core/src/fallback/agc.rs`; unit tests there compare with plain `u128` division at the edges of the domain, at random points and next to multiples of the divisor, and the tests `cq15_fallback_equals_reference_over_parameter_corners` and `agc_cq15_fallback_matches_the_reference_at_the_parameter_extremes` compare the kernels.

Timing: ratio `1/1`, group delay 0. The kernel is a per-sample feedback loop (the gain of every sample depends on the output of the previous one); the recursion is not accelerated, only the magnitudes and the products of `C32` are computed in vectors (see above). The C32 golden case `steps_c32_24000` reaches 125.5 dB against the f64 model (limit 80 dB; the float32 model of `cases/agc.py` gives the values of the fallback bit for bit), so the bit-exact fallback of the milestone text is not used.

### `squelch`

`SquelchState<T>::new(threshold_db, hysteresis_db, tau_s, rate)` creates a power gate for `C32` or `CQ15`. `threshold_db` is the open level in dBFS (`-150` to `0`; a complex sample with `|x|^2 = 1` is 0 dBFS), `hysteresis_db >= 0` lowers the close level to `threshold_db - hysteresis_db`, `tau_s > 0` is the time constant of the power average. `alpha = 1 - exp(-1 / (fs * tau_s))` is computed in f64 and must lie in `(0, 0.5]`; every violation (also NaN and infinity) gives `InvalidParameter`. The state starts closed with `p = 0`; `reset()` returns to that; `set_thresholds(threshold_db, hysteresis_db)` validates like `new`, changes only the two levels (nothing on error) and applies from the next sample, `p` and the gate are kept; `is_open()` and `average_power()` (linear, full scale 1.0) read the state.

Per sample, in this order: update the average power, update the gate (open when `p >= P_open`, closed when `p < P_close`, otherwise unchanged), then write `x` when the gate is open and zero when it is closed. The gate is evaluated before the sample is written, so the first sample that lifts `p` to `P_open` is already passed.

- `C32`: `alpha` as `f32`; `P_open = 10^(threshold/10)` and `P_close = 10^((threshold - hysteresis)/10)` in f64, cast to `f32`; `q = re*re + im*im`; `p = flush_denormal(p + alpha * (q - p))`, all f32 operations one at a time without FMA. A non-finite `q` (NaN or infinity in the input, or an overflowing product) leaves `p` and the gate unchanged; the sample itself is passed or zeroed by the current gate state, so NaN and infinity reach the output of an open gate unchanged. Closed output is `(+0.0, +0.0)`.
- `CQ15`: `alpha_q31 = floor(alpha * 2^31 + 0.5)` as `i64` (Q31); the levels are `floor(10^(db/10) * 2^61 + 0.5)` as `i64` (Q61); `q = re^2 + im^2` of the raw values (Q30, at most `2^31`); the average `p` is Q61 and `p = p + alpha_q31 * (q - round_shift(p, 31))` in `i64`. The step is not rounded, so the average follows powers down to the input resolution and keeps long time constants exact (the product is at most `2^61`, `p` at most `2^62`). A decaying average stops below `2^-31` (-93.3 dBFS), one step before zero, so the close level `threshold_db - hysteresis_db` must be at least -90 dB (`CQ15_MIN_CLOSE_DB`, the power of one input LSB), and `alpha_q31` must not round to zero (`fs * tau_s` below about `4 * 10^9` samples); otherwise `new` and `set_thresholds` give `InvalidParameter`.

**The float32-model rule.** The gate decision is discrete, so an f64 reference could switch the gate one sample earlier or later than the fallback, which makes a tolerance comparison meaningless. The arithmetic of both types is therefore fixed by the specification above, `Reference` performs exactly the same operations as `Fallback` (f32 for `C32`, exact `i64` for `CQ15`) and the class is *bit-exact* for both types. The golden cases of `C32` are computed by `tests/golden/sdrk_golden/f32model.py`, which evaluates every operation on NumPy `float32` scalars one at a time (never fused), the cases of `CQ15` by an integer model like the Q15 model; the JSON of a float32-model case says `"model": "float32"`. Timing: ratio `1/1`, group delay 0. The kernel is a first-order recursion on `p` and is not accelerated.

### Windows, `window`, `mag_sq`, `power_db`

`sdrk_core::window` writes windows into caller slices of `f32` or `Q15` (computed in f64 with `libm`): `hann`, `blackman_harris` (4-term, `a0 = 0.35875`, `a1 = 0.48829`, `a2 = 0.14128`, `a3 = 0.01168`), `kaiser(out, beta, sym)` (`beta` finite and not negative), `bessel_i0` (power series, at most 500 terms) and `window_gain(&[f32]) -> (coherent gain, noise-equivalent bandwidth)`. `Symmetry::Symmetric` uses the denominator `N - 1`, `Symmetry::Periodic` the symmetric window of length `N + 1` without its last value (`scipy.signal.get_window(..., fftbins=True)`); a window of length 1 is `[1.0]`, an empty slice is accepted. A symmetric window is symmetric bit for bit. The periodic Hann window has `(0.5, 1.5)` as gain and bandwidth. In `Q15` the peak 1.0 saturates to 32767.

`window(input, output, w)` multiplies per component (`w.len() == input.len()`): `f32` as a plain f32 multiply (equal to the f64 product rounded once because the product of two f32 values is exact in f64), `Q15` with `q15_mul`. `mag_sq` computes `re * re + im * im` (`f32`, no FMA) or `sat16(round_shift(re^2 + im^2, 15))` (`Q15`, full-scale samples saturate to 32767). `power_db(input, output_f32, offset_db)` computes `10 * log10(max(p, 1e-20)) + offset_db` with `libm::log10f` on the f32 power (`Q15` input is `raw / 32768`; the reference uses `libm::log10` in f64). Negative, zero and NaN input count as `1e-20` (so -200 dB plus the offset), and the kernel never panics.

### FFT: `fft`, `rfft`, `irfft`

`kernels::fft` provides the heap-free FFT as an ordinary kernel: power-of-two sizes 16 to 65 536, in place, iterative radix-2 decimation in time, for `C32` and `CQ15` (trait `Fft<T>`), plus a real-input FFT and its inverse for `f32` (trait `RealFft`). `FftPlan<T, Tw>` holds the size and the twiddle table `tw[k] = e^(-j 2 pi k / N)` (`k < N/2`) in caller storage (`[T; N/2]`, `&mut [T]`, `Vec<T>`, a `static`); `FftPlan::new` fills it (f64 `libm::cos`/`libm::sin`, then a cast for `C32` or the Q15 rule for `CQ15`), `FftPlan::from_twiddles` only validates the length. `RealFftPlan` wraps a complex plan of size `N/2` plus the post-processing twiddles `post[k] = e^(-j 2 pi k / N)`; one plan serves `rfft` and `irfft`. The optional feature `static-twiddles` of `sdrk-core` (independent of the backend feature `fft-tables` below) adds `TWIDDLES_C32_4096` (16 KiB of flash) and `TWIDDLES_CQ15_4096` (8 KiB) emitted by `build.rs` and `FftPlan::<T, _>::from_static_4096(n)` for `n <= 4096`, which uses every `4096 / n`-th entry; the result equals a plan from `new` bit for bit.

**Twiddles in the SIMD backend.** A plan's table is the only twiddle source of the fallback. The SIMD backend can use other sources (decision D4), so for a plan from `FftPlan::from_twiddles` with values other than those of `new` its result is not the transform of those twiddles:

- `C32` with the backend feature `fft-tables` (on by default on x86-64 and AArch64 through the facade, opt-in on wasm32 with the facade feature `fft-tables`): the passes of spans up to 4096 read static per-span tables equal to the twiddles of `new`; the plan's table serves only the spans above 4096. Without the feature, `W^3k` is the product `W^k W^2k` of two plan entries.
- `rfft`: the bins `N/2 - k` use `-conj(post[k])` in place of `post[N/2 - k]` (the identity of the twiddles of `RealFftPlan::new`), and with `fft-tables` the post-processing of up to 4096 points reads the static table of the span `N` instead of `post`.
- `CQ15`: the generic bit-exact path relies on `|wr| + |wi| <= 46341`, which holds for plans from `new` and `from_static_4096`; the radix-4 level paths clamp twiddles to `>= -32767`. Stride plans with a twiddle step above 4 per stage square `w^k` instead of loading `w^2k`, which costs up to about 1 dB at N = 16.

**One scale rule for every type and direction.** The call returns `FftScale { exponent }`; the unnormalised sum `sum x[n] e^(-+j 2 pi k n / N)` equals `output * 2^exponent`.

| Type | Direction | Output | `exponent` |
| --- | --- | --- | --- |
| `C32` | Forward | `X[k] = sum x[n] e^(-j 2 pi k n / N)` (like `numpy.fft.fft`) | 0 |
| `C32` | Inverse | `(1/N) sum X[k] e^(+j 2 pi k n / N)` (like `numpy.fft.ifft`) | `log2 N` |
| `CQ15` | Forward, `Scaling::Default` | `X[k] / N` (halved after every stage) | `log2 N` |
| `CQ15` | Inverse, `Scaling::Default` | `(1/N) sum X[k] e^(+j ..)` (halved after every stage like CMSIS-DSP; cannot overflow for `abs(x) <= 1`; forward then inverse returns `x / N`, use block floating point when precision matters) | `log2 N` |
| `CQ15` | both, `Scaling::BlockFloat` | transform divided by `2^e`, `e` = sum of the stage shifts (0, 1 or 2 per stage) | `e` |
| `f32` real | `rfft` | `N/2 + 1` bins like `numpy.fft.rfft` | 0 |
| `f32` real | `irfft` | `N` samples like `numpy.fft.irfft(X, n=N)` | `log2 N` |

`Scaling::BlockFloat` with `C32` is `Unsupported`. `data.len()` must equal `plan.len()` (`LengthMismatch`); a size that is not a power of two or outside 16 to 65 536 is `InvalidParameter` and a twiddle table of the wrong length is `LengthMismatch`.

**Displaying spectra from a Q15 FFT.** `power_db(|X_out|^2) + 6.0206 * exponent` is the level relative to the unnormalised transform (each halving is a factor 4 in power, +6.02 dB).

**Fallback order of operations.** (1) Bit-reversal permutation in place. (2) For stage `s = 1 .. log2 N`: `half = 2^(s-1)`, `stride = N / 2^s`; for each block and `k < half`: `w = tw[k * stride * tw_stride]` (`conj(w)` for the inverse), `t = w * c`, `data[b+k] = a + t`, `data[b+k+half] = a - t`. (3) `C32`: complex multiply `(wr cr - wi ci, wr ci + wi cr)` without FMA; the inverse multiplies every output by `1.0 / N` (exact). (4) `CQ15`: the twiddle product is rounded `round_shift(.., 15)` in `i64` without saturation (it can reach about 46 341); the butterfly sum is shifted with rounding (`round_shift(a +- t, shift)`) and saturated once. *Fixed*: shift 1 in every stage. *Block floating point*: before each stage `m` is the largest absolute component of the whole block; a butterfly output can reach `(1 + sqrt 2) m`, so the shift is 2 for `m > 27145`, 1 for `m > 13572`, else 0, and the exponent adds up the shifts. With this rule no butterfly saturates for input of complex magnitude up to 1 (tested for random and structured input of every size 16 to 4096). A corner sample such as `(32767, 32767)` has magnitude sqrt 2 and may still saturate in the first stage.

**Real FFT.** With `z[n] = x[2n] + j x[2n+1]` and `Z = FFT_{N/2}(z)`, `Z[N/2] := Z[0]`: `E = (Z[k] + conj(Z[N/2-k])) / 2`, `O = (Z[k] - conj(Z[N/2-k])) / 2`, `X[k] = E - j post[k] O` (`post = -1` for `k = N/2`). The inverse mirrors it: `E = (X[k] + conj(X[N/2-k])) / 2`, `D = (X[k] - conj(X[N/2-k])) / 2 * conj(post[k])`, `Z[k] = E + j D`, `z = IFFT_{N/2}(Z)`, `x[2n] = Re z[n]`, `x[2n+1] = Im z[n]`; the imaginary parts of bin 0 and bin `N/2` are ignored, as in NumPy. Scratch of `N/2` complex samples is passed by the caller.

**Reference.** `Reference` computes the naive O(N^2) DFT in f64 (`libm::cos`/`sin` of `2 pi ((k n) mod N) / N`, the product reduced in integers first). A DFT cannot run in place without a second buffer, so `Reference::dft(input, output, dir, scaling)` is the out-of-place form without a size limit (used by the suite for N = 1024), and the in-place trait method `Fft::fft` of `Reference` copies to a stack buffer and accepts up to `REFERENCE_IN_PLACE_MAX` = 256 points (`Unsupported` above). For `CQ15` the reference returns `round(X / N)` with exponent `log2 N` in both scaling modes; comparisons multiply both sides by `2^exponent` first. `rfft`/`irfft` of the reference are direct sums and need no scratch.

**Contract notes.** The first estimate for the block-floating-point full-scale tone was 60 dB; the exact algorithm above reaches 59.05 dB for the golden input because the conservative first stage (`m > 27145` gives shift 2) costs one bit, so the stored threshold is 58 dB (analysis in the decisions log). Fixed scaling reaches 62.75 dB on the same input. The golden cases are `fft/{c32_fwd_{16,64,1024,4096}, c32_inv_1024, rfft_f32_{32,1024,4096}, irfft_f32_{32,1024,4096}, cq15_fixed_tone_1024, cq15_fixed_noise_{1024,4096}, cq15_fixed_inv_1024, cq15_bfp_tone_1024, cq15_bfp_noise_1024, cq15_bfp_weak_tone_1024}`; the block-floating-point cases are compared after multiplying by `2^exponent`.

### `convert_out` and `convert_out_real`

`ConvertOut<T>::convert_out(&format, input, output) -> Result<usize>` encodes whole samples into the raw bytes of `format` (layout `Interleaved` or `Planar`) and returns the number of bytes written; `ConvertOutReal<T>` does the same for `Layout::Real`. It is the inverse of `convert` with rounding and saturation. The effective integer value `e` of a component is first computed as below, then stored as in `docs/device.md`: `Msb` alignment shifts `e` left by `container_bits - bits`, `Lsb` alignment stores `e` sign-extended in the container (the decoder ignores the bits above `bits`), the I/Q swap puts Q first in every pair, a planar stream holds all I values and then all Q values, `Endian::Big` writes multi-byte containers big-endian, and `Packed12`/`Packed10` pack their values LSB-first (alignment and byte order do not apply). Errors: `BufferTooSmall { needed, got }` when `output` cannot hold `format.bytes_for_samples(input.len())` bytes, `Unsupported` for `Bits1`, `InvalidParameter` for a layout of the wrong kind and for a sample count that does not fill whole packing groups (checked in this order: layout, `Bits1`, packing, buffer). Bytes beyond the returned count are not touched.

- **From `C32`/`f32`:** `v = x * full_scale + offset` in f64 (`offset = 127.5` for `U8`, else 0; NaN counts as amplitude 0). `e` is `v` rounded to the nearest integer with ties to even (like VOLK; `libm::roundeven`), saturated to the range of the format: `0 ..= 2^bits - 1` for `U8`, `-2^(bits-1) ..= 2^(bits-1) - 1` for signed formats; infinities saturate. `F32` containers copy the bits of `x` (NaN payloads and `-0.0` included). For `U8` every amplitude that is a multiple of `1 / full_scale` is a tie: 0.0 gives 128 and 1/128 also gives 128. On bare-metal 32-bit Arm and RISC-V (`target_os = "none"`), where `f64` is emulated in software, the fallback computes the same `e` in integer arithmetic from the exponent and mantissa of `x` for every format without offset whose full scale is a power of two up to 2^21 and whose range lies within `±2^22` (`CS8`, `CS16`, `SC16_Q11`, `PACKED12`, `PACKED10` and their variants); the result is identical for every f32 (checked over all 2^32 inputs at every scale 2^0 to 2^21).
- **From `CQ15`/`Q15` (integer only):** `div_even(a, d)` is `a / d` rounded to the nearest integer, ties to even. `U8` with a power-of-two full scale: `e = clamp(div_even(q + 255 * 2^(15 - bits), 2^(16 - bits)), 0, 2^bits - 1)`, which is `div_even(q + 32640, 256)` for 8 bits. `U8` with the explicit full scale `n`: `div_even(q * n + 255 * 16384, 32768)`. Signed with a power-of-two full scale and at most 16 bits: `sat_b(div_even(q, 2^(16 - bits)))`. More than 16 bits: `q << (bits - 16)`. Signed with the explicit full scale `n`: `sat_b(div_even(q * n, 32768))`. `F32` containers get the exact `q / 32768`. These integer rules equal the f64 formula applied to `x = q / 32768` for every format, which the reference uses.
- **Round trips:** decoding then encoding the raw bytes of a non-lossy format (at most 24 bits for `C32`, at most 16 bits and a power-of-two full scale for `CQ15`) reproduces them exactly; encoding then decoding stays within half an LSB of the format for amplitudes inside its range.
- **Reference:** the f64 formula with a bit-by-bit writer. The fallback uses the integer formulas above for `Q15`.

### `fir_interpolate` and `fir_interpolate_real`

`FirInterpState<T, Taps, Hist>` (complex signals; `FirInterpRealState` for `f32`/`Q15` signals) holds the real taps designed at the *output* rate (the interpolation gain `L` is part of the taps; the caller includes it), the factor `L >= 1` and a history of `ceil(N / L)` input samples (`new(taps, history, factor)` validates like `ResampleState`, `reset()`, `factor()`, `taps()`, `history()`, `phase()`). It is the resampler with `up = L` and `down = 1`: `upfirdn(h, x, L, 1)` restricted to the outputs that depend on received input, so every input sample yields exactly `L` outputs. Like the resampler it consumes an input sample only while the output has room for its outputs (partly produced samples stay pending) and returns `Progress { consumed, produced }`. Timing: ratio `L/1`, group delay `Delay::new(N - 1, 2 * L)` input samples. A `CQ15` filter cannot hold a tap gain above 1 in a single tap sum; the golden case `fir_interpolate/l5_n241_cq15_4000` divides the taps by `L` (a documented gain loss of 5). The fallback and the reference call the `resample` implementations.

### `fm_mod`

`FmModState::new(deviation_hz, rate)` holds the 32-bit phase accumulator (units of 2 pi / 2^32; `phase()`, `set_phase()`, `reset()`) and the scale `k = deviation_hz / rate * 2^32` (`scale()`); a deviation that is NaN, infinite or negative is `InvalidParameter`. `FmMod<T>::fm_mod(state, input, output)` (equal lengths) does, per sample, `phase += floor(x * k + 0.5)` (the step is computed in f64, converted to `i64` and wrapped into `u32`; NaN counts as a step of 0, infinities saturate in the `i64` conversion) and writes `e^{j 2 pi phase / 2^32}` from the cosine tables and the linear interpolation of `rotate`, i.e. `rotate` applied to a unit vector without the final multiplication: the `CQ15` output has the table amplitude `1 - 2^-15`. `Q15` input is `x = q / 32768` in f64 before the formula. Timing: ratio `1/1`, group delay 0. The reference computes `cos`/`sin` of the exact angle in f64 (amplitude `1 - 2^-15` for `CQ15`); with float32 input and 75 kHz at 240 kHz `k * x` is an integer for almost every `x`, so the golden cases `fm_mod/dev33k_fs192k_*` use a deviation that makes the rounding of the step visible.

### Fused kernels: `ddc`, `duc`, `fm_demod`

Each fused kernel is a trait in `sdrk_core::kernels::fused` and a generic chaining function in `sdrk_core::fused`: `ddc_chained(k, nco, fir, input, output, scratch)`, `duc_chained(k, fir_interp, nco, input, output, scratch)` and `fm_demod_chained(k, quad, deemph, input, output_audio, scratch_real, gain)`. `k` is any implementation of the single kernels. `Fallback` and `Reference` implement the traits by calling the chaining function with `self`; the facade `Sdrk` does the same with itself, so a fused kernel uses the best single kernel for every step (`backend_for("ddc", ..)` reports `chained`).

- **`ddc`:** `rotate` followed by `fir_decimate`. It processes `n_in = min(input.len(), scratch.len(), fir.max_input_for_output(output.len()))` input samples (`FirDecimState::max_input_for_output(out_len) = countdown + out_len * factor`, the largest input whose outputs fit), rotates exactly `input[..n_in]` into `scratch[..n_in]` (the oscillator advances by exactly `n_in`), decimates that block and requires that all `n_in` samples are consumed (`Internal` otherwise). The oscillator phase is therefore exact however small the output buffer is; the caller resubmits `input[consumed..]`. Returns `Progress { consumed: n_in, produced }`.
- **`duc`:** `fir_interpolate` followed by `rotate`. It interpolates `min(input.len(), output.len() / L, scratch.len() / L)` whole input samples into `scratch` and rotates the interpolated samples into `output`; returns the `Progress` of the interpolator (`produced = L * consumed`).
- **`fm_demod`:** `quad_demod` into `scratch_real`, then `deemphasis` into `output_audio` (`output_audio.len() == input.len()`, else `LengthMismatch`). The input is processed in pieces of `scratch_real.len()` samples with both states carried over, so the result does not depend on the scratch size; a scratch of length 0 with a non-empty input is `BufferTooSmall`.
- **The rule for backends:** a truly fused version of a backend must be **bit-identical** to the chained result of the same backend's single kernels and is kept only if it needs fewer instructions (decision table). The tests `*_equals_chain` compare every fused kernel with the hand-written chain bit for bit for random chunk plans and small buffers.

### `dot` and `dot_real`

`Dot<T>::dot(x, taps)` (`T` complex, `taps: &[T::Real]`) and `DotReal<T>::dot_real(x, taps)` (`T` real, `taps: &[T]`) return `sum x[i] * taps[i]` over ascending `i`; the lengths must be equal (`LengthMismatch { expected: x.len(), got: taps.len() }`), and empty slices give zero. They are stateless and have no output buffer, so they are the smallest kernel of the library; the tunable resampler of `sdrk-blocks` calls them for every output (two per sample, one per neighbouring phase). `f32` and `C32` accumulate in `f32`, ascending, without fused multiply-add (the same rule as `fir`); `Q15` and `CQ15` accumulate the Q30 products in `Acc64`, and round, shift and saturate once at the end, so a sum whose partial sums leave the Q15 range but whose total does not is exact. The reference sums in f64 (`f32`) and in `i64` (`Q15`). Golden cases `dot/{c32,cq15}_{7,64,1023}` and `dot/{f32,q15}_{7,1023}` compute 256 sliding windows each.

### Testkit meters and the end-to-end chains

`sdrk_testkit::fm::fm_baseband(out, rate_hz, carrier_offset_hz, deviation_hz, audio_hz, audio_amp, start)` writes a unit-amplitude FM signal whose phase is integrated analytically, `2 pi frac(offset n / rate) + beta (1 - cos(2 pi frac(audio_hz n / rate)))` with `beta = deviation * audio_amp / audio_hz` (the constant makes the phase start at 0), so chunked generation is exact. `meters::ToneMeter::measure(signal, rate, freq)` fits `a cos + b sin + dc` by least squares and returns `Tone { amplitude, phase, dc, residual_power }` (`x ~ amplitude cos(2 pi f n / rate + phase) + dc`); `meters::sinad_db` is `10 log10(total_power / residual_power)` with the total power taken without the fitted offset; `meters::fit_frequency(signal, rate, guess, span)` finds the tone frequency by minimising the residual; `meters::estimate_frequency(signal, rate)` is the peak of a 4x zero-padded f64 DFT of at most the first 2048 samples with parabolic interpolation; `meters::spectral_mask(signal, rate, &[(f_lo, f_hi, max_db)])` averages Hann-windowed direct DFTs of non-overlapping segments of 1024 samples and requires every bin in a band to be at most `max_db` below the strongest bin (it returns the first `MaskViolation`; cost `2 * 1024 * length` multiply-adds). All meters are direct f64 sums and do not use the FFT kernel. `design_helpers::lowpass_hann(cutoff_norm, taps)` is the symmetric-Hann windowed-sinc low-pass of the end-to-end tests until the designer of M09 exists (`cutoff_norm = cutoff / fs`, DC gain 1).

`sdrk_testkit::e2e` holds the two streaming chains in blocks of 500 samples at 2.4 MHz without heap: `fm_rx` (raw bytes, `convert`, `ddc` with the NCO at -600 kHz and 127 `lowpass_hann` taps (100 kHz / 2.4 MHz) decimating by 10, `fm_demod` at 240 kHz with 50 us de-emphasis, `resample_real` 1/5 with 241 taps (15 kHz / 240 kHz) to 48 kHz audio) and the transmitter `FmTx` (1 kHz audio, `fir_interpolate_real` by 5 with `5 * lowpass_hann`, `fm_mod` with 75 kHz deviation at 240 kHz, `duc` by 10 with `10 * lowpass_hann` and the NCO at +600 kHz, `convert_out` to `CS8`). `measure_rx` (synthetic broadcast with amplitude 0.9 encoded to `CU8`) and `measure_txrx` run them over a number of samples and measure the last half of the audio. The discriminator gain is `fs / (2 pi * 75 kHz)` for `C32` (full deviation gives +-1.0) and raw 32767 for `CQ15`, whose output unit is phase / pi, so the full deviation is 0.625 there (SINAD does not depend on the amplitude). Thresholds (SINAD of the 1 kHz tone, audio frequency within 0.1 Hz): RX `f32` 40 dB and `Q15` 35 dB, TX then RX `f32` 35 dB and `Q15` 30 dB. Measured with the fallback kernels: about 74 dB for RX and 68 dB for TX then RX in both sample types, so the thresholds leave a wide margin; the transmit spectrum is at least 45 dB down outside 400 to 800 kHz (the DC offset of the 8-bit encoder is the strongest spur, at -51 dB).

## How kernels are tested

Every kernel is covered by three layers, all provided by `sdrk-testkit`:

1. **Golden vectors** (M04) and the **reference**: the fallback is compared with `Reference` (bit-exact kernels with `bit_exact`, tolerance kernels with `compare_complex` and the SNR from the contract table).
2. **Block-size invariance** (R6.2): stateful kernels and blocks must produce identical bits however the input is split. `check_block_invariance(input, out_whole, out_chunked, ChunkPlan::new(seed, max), make_state, step)` runs `step` once over the whole input and once over random chunk sizes (deterministic PCG32) and reports the first differing output index. `step` may consume less than it is offered; the harness resubmits the rest. Stateless kernels such as `scale` pass it trivially and are still registered, so the harness itself stays covered.
3. **Extreme inputs**: `r#gen::extreme::silence`, `full_scale_alternating` (`+-(1 - 2^-15)` on both components) and `f32_specials` (0.0, -0.0, NaN, +inf, -inf, a denormal, `f32::MAX`) feed every kernel. A kernel must not panic, must saturate Q15 results and must keep feedback state finite (`flush_denormal`).

Test inputs come from deterministic generators (`r#gen::tone`, `noise`, `chirp`, ...) that depend only on the absolute sample index, so chunked and whole generation agree bit for bit. Raw device formats are checked against the independent oracle `encode::encode` / `encode::decode_reference`, never against the code under test.

## Backends and the numeric contract

The SIMD backend ([backends.md](backends.md)) implements `convert`, `convert_out`, `rotate`, `fir`, `fir_decimate`, `fir_interpolate`, `resample`, `mag_sq`, `mag`, `quad_demod`, `fm_mod` and `fft` for `C32` and `CQ15`, `agc` for `C32`, and `rfft`/`irfft` for `f32` around its `C32` FFT.

- **Bit-exact with the fallback:** `convert`, `convert_out`, `mag_sq` and `fm_mod` (both types, in every build), and for `CQ15` also `rotate`, `fir`, `fir_decimate`, `fir_interpolate` and `resample`.
- **Tolerance kernels in the backend:** `C32` `rotate` (120 dB), `fir`, `fir_decimate`, `fir_interpolate`, `resample` and `fft` (110 dB), `f32` `rfft` and `irfft` (110 dB), `quad_demod` (100 dB `C32`, 70 dB `CQ15`), and `CQ15` `fft` (the SNR contract of the table: 58/55 dB block float, 55/40 dB fixed scaling; fixed scaling within 1 dB of the fallback at every size; the block-floating-point exponent may differ from the fallback's). They reach the minimum SNR of their contract against the f64 reference but not the bits of the fallback, and different levels (SSE2, AVX2, NEON) give different bits within that tolerance. In the relaxed WASM build (feature `relaxed-simd`, [backends.md](backends.md)) the `C32` variants of `fir`, `fir_decimate`, `fir_interpolate`, `resample`, `rotate` and `fft` use relaxed multiply-add (and with it `rfft` and `irfft`, through the `C32` FFT): they stay within their contracts, but the bits depend on the host CPU.

Block-size invariance (R6.2) holds for each kernel of the backend, per level.
