## Phase 8 — further bindings (optional, only on concrete demand)

- **C bindings** (`bindings/c`): `extern "C"` API mirroring the WASM API (pipeline from JSON, push/pull, outputs, events, params), opaque handles, error codes = `ErrorKind` numbers, header generated with `cbindgen` (checked in, verified by CI).

- **Generic building blocks for framed digital modes (noted 2026-11-28 after the analysis of a TETRA recording, see [signal-analysis-notes.md](../signal-analysis-notes.md) and [tetra-decoder-gaps.md](../tetra-decoder-gaps.md); not scheduled).** Rule for every item: a kernel or block is defined by its algorithm and its parameters, not by a standard. A standard is a **preset** (a named parameter set, documented with its source clause) and a test case; no kernel has a code path of its own for one standard. The users named below are the ones that motivated the parameter ranges; the parameters of every preset are taken from its standard when the milestone is written (the values given here for TETRA are from ETSI EN 300 392-2 V3.8.1, the others are to be checked). Order of use: the channel-coding items (`viterbi`, `puncture`, `crc`, `interleave`, `additive_scramble`, `block_code`) are needed by TETRA, DAB/DAB+ and DVB alike, so whichever of these is scheduled first defines them; the roadmap below then only adds presets. **Scheduled first: [M57](M57-tetra-bsch.md)** builds `viterbi` with `conv_encode` (zero tail), the index rule of `puncture`, the multiplicative block permutation of `interleave`, `lfsr` with the additive (de)scrambler as protocol functions, `crc` over bits, and the phase-step domain of `sync_detect` as a crate-internal building block, all with TETRA as the first preset; the other forms named here stay in this entry.
  - **`viterbi` (kernel and block) with `conv_encode`:** soft-decision Viterbi decoder for a convolutional code given by its **constraint length** K (3 to 9), its **generator polynomials** (one per output, n = 2 to 4 outputs per input bit; an inversion flag per output) and its **termination**: zero tail (known end state), tail-biting (the start state is unknown and equals the end state), or a stream with a traceback depth. Input: soft bits (`f32`; an `i16`/`i8` metric path for Q15 and the MCU targets), where a soft value of exactly 0 is an **erasure** (no information, as the depuncturer produces). Output: hard bits and a quality figure (the path metric margin, or the bit errors found by re-encoding). SIMD across the states: 16 states (K = 5) are one vector of `i16` metrics at 256 bit, 64 states (K = 7) four. Presets: TETRA (K = 5, n = 4, G1 = 1 + D + D^4, G2 = 1 + D^2 + D^3 + D^4, G3 = 1 + D + D^2 + D^4, G4 = 1 + D + D^3 + D^4, zero tail; EN 300 392-2 8.2.3.1.1), DAB (K = 7, n = 4), DVB-S/T and IEEE 802.11 (K = 7, n = 2), GSM (K = 5, n = 2), LTE (K = 7, n = 3, tail-biting). The encoder is the transmit side and the test source.
  - **`puncture` / `depuncture`:** a keep mask over the output of the mother code, given as a periodic pattern (one row per output, as the tables of DVB, 802.11 and DAB), as an index rule with periodic extra deletions (TETRA: b3(j) = V(k), k = 8 ((i-1) div t) + P(i - t ((i-1) div t)), and for the rates 292/432 and 148/432 i = j + (j-1) div 65 or 35; 8.2.3.1.2 to 8.2.3.1.6), or as an explicit list; applied per block (restarted at every block) or on a stream. The depuncturer inserts erasures (soft value 0). Kept apart from `viterbi`, so that rate-compatible codes, unequal error protection (DAB) and other decoders share it.
  - **`rs_decode` / `rs_encode`:** Reed-Solomon over GF(2^m), m = 3 to 8, with the field polynomial, the first consecutive root and the root spacing of the generator as parameters, any (n, k) with shortening, errors and erasures. Presets: DVB RS(204,188) (shortened (255,239)), DAB+ RS(120,110) (shortened (255,245)), CCSDS (255,223) with the dual-basis option, the GF(64) codes of P25.
  - **`block_code` (small linear block codes):** encoder and decoder for an (n, k) code given by its generator (or parity-check) matrix, n up to 32, k up to 16. Soft maximum-likelihood decoding by correlation with all 2^k codewords, or faster for codes built from first-order Reed-Muller codes through `fwht` (M56: a first-order Reed-Muller code is decoded by one Walsh-Hadamard transform, a second-order one as a set of its cosets); hard decoding by a syndrome table. Presets: the shortened (30,14) Reed-Muller code of the TETRA AACH (8.2.3.2, generator matrix in the standard), Golay (23,12) and (24,12), Hamming codes, BCH(31,21) of POCSAG, QR(16,7) of DMR.
  - **`crc` (bit level, `sdrk-proto`, with a check block):** one generic CRC of width up to 32 with polynomial, initial value, reflected input and output, final XOR, over **any number of bits** (not only whole bytes); the block appends or checks it and sets `CRC_OK`. The byte CRCs of M37 (`crc16_x25`, `crc16_ccitt_false`, `crc32`, `crc24_adsb`) become presets of it with their fast byte tables kept. TETRA uses the (K1 + 16, K1) code of 8.2.3.3 (generator X^16 + X^12 + X^5 + 1 as in ITU-T X.25) on 60, 124 and 268 bits.
  - **`interleave` / `deinterleave`:** (1) a **block permutation** of N soft bits, given by a rule or a table: row-column (R x C with the read order), multiplicative (k = 1 + ((a i) mod K): TETRA (120,11), (216,101), (432,103), 8.2.4.1), quadratic congruence, bit reversal, or a table generated at build time (the frequency interleaving of DAB, the bit and symbol interleavers of DVB-T); (2) a **convolutional (delay-line) interleaver** with the branch delays as a list: the Forney interleaver of DVB (I = 12, M = 17), the time interleaving of DAB (16 branches, delays in whole frames from a bit-reversed index), interleaving over N blocks (TETRA 8.2.4.2). The delay lines take their storage from the arena; how long a delay a target supports (DAB: about 384 ms) is a maintainer decision per target.
  - **`lfsr` and `additive_scramble`:** a generic LFSR (Fibonacci and Galois form, polynomial up to degree 32, any initial state) that writes bits one by one or packed in the word order of the code format of M51 (shared conventions §B), so that the existing `Prbs5` to `Prbs11` become presets of it with the same bit order; the additive (de)scrambler XORs a bit or soft-bit stream with the sequence (a sign flip for soft bits), restarted per block or per frame or free-running, with the initial state as a **runtime** parameter (TETRA sets it from the colour code once the SYNC PDU is decoded). Presets: TETRA (c(x) of degree 32 with 15 terms, initial state from the 30-bit extended colour code and two ones, restarted per block, all zero for the BSCH; 8.2.5), DVB energy dispersal (1 + x^14 + x^15, restarted every eight packets), DAB energy dispersal (x^9 + x^5 + 1), IEEE 802.11 (x^7 + x^4 + 1). The multiplicative `bit_scramble` (M44.2) stays as it is.
  - **`sync_detect`:** one block for known patterns, matched in a **domain** chosen by parameter: complex samples (a preamble, through `correlate` of M50), soft bits (a sync word, with a soft or Hamming distance), or the **phase steps** of symbols (a differential template, insensitive to a carrier offset up to a fraction of the symbol rate; the TETRA frequency correction field and training sequences). Several templates at once (burst types). Output: events as packets with the position (sample or symbol index), the template, the score, and where the domain gives them the phase, the **frequency offset** (the angle of the differential correlation) and the orientation (I/Q swapped or not); peak picking with a threshold and a minimum distance. A prototype of the phase-step domain is the function `tetra_sync` of the analysis prototype (outside the repository; method in [signal-analysis-notes.md](../signal-analysis-notes.md) §6.2).
  - **`frame_clock` (TDMA and frame flywheel):** a period in symbols or samples with a list of nested counters (TETRA: 255 symbols per slot, 4 slots, 18 frames, 60 multiframes; others: the slots of DMR and GSM, the frames of DAB), locked to the events of `sync_detect`, carried through missing events with a miss counter, its counters set from a decoded field (the TETRA SYNC PDU carries timeslot, frame and multiframe numbers); outputs the position in the hierarchy for every slot. A part for controllers in the style of `LockWatch`.
  - **`field_demux` and `bitfield_parse` (tables, not code):** `field_demux` cuts a frame of N soft bits into fields by a table per frame type (offset, length, tag; a field may come in parts, as the broadcast block of a TETRA normal burst around its training sequence), the frame type given by `sync_detect`; `bitfield_parse` turns a decoded bit block into named fields by a description table (length, name, values; optional elements with a presence bit; nested elements), output as JSON text packets like `adsb_parse`. One engine for the PDUs of TETRA, the FIGs of DAB, the CSBKs of DMR and similar.
- **Roadmap DAB / DAB+ and DVB (maintainer discussion of 2026-11-15; not scheduled, each step a milestone of its own).** Builds on the building-block concept of M44.1: small blocks with one task each, composites with a controller (state machine), the shared supervisor `LockWatch`, feedback only inside composites, soft bits of `symbol_demap`. DVB-C is single-carrier QAM (M44.2 gives 256-QAM) and needs only steps 1 and the transport layer of step 6; DVB-T2 and DVB-S2 (LDPC + BCH) come last, if at all. The standards (ETSI EN 300 401 DAB, TS 102 563 DAB+, EN 300 744 DVB-T) are free; the known open implementations (welle.io, dablin, gr-dab, gr-dvbt) are mostly GPL and serve as comparison only (clean room, as for rtl_433).
  1. **FEC with SIMD:** the generic `viterbi` (with `puncture`) and `rs_decode` of the building blocks above, with the DAB and DVB parameter sets as presets (K = 7, the punctured codes of DAB and DVB-T/S; RS(204,188) of DVB, RS(120,110) of DAB+), each a kernel with SIMD paths and cycles per sample against an established library. SIMD comes before threads: a SIMD Viterbi gains roughly 8 to 16 times per core. If TETRA or another user schedules these kernels first, this step only adds the presets and their tests.
  2. **Multithreaded runner:** node groups run on threads, bit-identical to the single-threaded runner (PLAN: "multi-threaded = single-threaded, bit-identical"); packet and frame edges may cross groups (lifts D517); hand-overs in batches of several OFDM symbols so that the thread overhead stays small. Uses: pipeline parallelism (sync + FFT | equalize + demap + deinterleave | Viterbi | RS + transport), the Viterbi on overlapping pieces of the stream, Reed-Solomon per packet, one DAB subchannel per thread.
  3. **OFDM core:** the reserved lane blocks (`fft`/`ifft`, `to_lanes`/`from_lanes`, `subcarrier_map`/`subcarrier_demap`), M55 `pilot_equalize`, and two gaps of the composition tools: a `Chain` that carries `Lanes<T>` (today lane blocks are wired by hand, `Lanes` is not a `ChainItem`) and frames on lanes (one OFDM frame = n lane steps). The blocks take several symbols per call and split subcarriers, so that step 2 can run them data-parallel; differential demodulation across OFDM symbols (DAB) as a small lane block.
  4. **OFDM synchronisation** (a composite with a state machine and `LockWatch`, the pattern of `qam_demod` in M44.1): coarse timing (DAB: the null symbol; DVB-T: the autocorrelation of the guard interval), the fractional frequency offset from the phase of that correlation, the integer offset by correlation with the phase reference symbol (DAB) or the continual pilots (DVB-T), fine timing from the channel impulse response, sampling clock tracking that steers `resample` inside the composite, the common phase error per symbol, and the position in the frame (DAB symbol count, DVB-T TPS).
  5. **DAB, then DAB+:** frequency and time deinterleaving (presets of the generic `interleave`: the generated frequency table and the 16-branch delay-line interleaver; 16 frames, about 384 ms: storage from the arena; which targets support it is a maintainer decision, for example one subchannel on Cortex-M), energy dispersal (a preset of `additive_scramble`), the FIC (ensemble, services, labels), subchannel extraction with a demux convention for many services (`Fork` has two branches only: packets tagged with the subchannel and a small demux block), MP2 frames; DAB+ adds the superframe (firecode, RS) and AAC frames for an external decoder.
  6. **DVB-T:** scattered and continual pilots, TPS, the inner bit and symbol interleavers and the outer convolutional interleaver (presets of `interleave`), RS (`rs_decode`), energy dispersal (a preset of `additive_scramble`) and MPEG-TS packets (188 bytes) as output for an external player; no video decoding in SDRk. Input rate 64/7 MHz for 8 MHz channels through `resample`.
- **Analysis blocks** with structured results (frames/events): signal detection (frequency, bandwidth, level, SNR), occupied bandwidth, noise floor, burst detection, instantaneous values and histograms, symbol-rate estimator. Extended on 2026-11-28 by the steps that identified a TETRA signal ([signal-analysis-notes.md](../signal-analysis-notes.md), the method in §2 of the notes): in-band signal detection (the power of the whole band hides a narrow signal), the symbol rate from the lines of the envelope spectrum, the roll-off from the edges of the spectrum, the time structure (power statistics, burst and frame period by autocorrelation), modulation features (the lines of the powers s^p of the symbols with their ambiguity of 1/p cycle per symbol resolved against a coarse carrier estimate, the alternation of even and odd symbols, the histogram of the phase steps, the FM discriminator histogram), the carrier from a known tone or template, and a check of carriers against a channel raster. Every figure carries a validity flag (the SNR it needs); the output format (JSON text packets or frames of fixed layout) is a decision for the first milestone.
- **Digital modes after M44:** diagram data as frames (constellation, eye diagram); `sync_detect` (now one of the generic building blocks above; M37–M44 synchronize on bits); forward error correction beyond the generic building blocks above (LDPC, turbo codes such as the PCCC of TETRA TEDS, polar codes); CQ15/Q15 variants of the digital blocks (M38–M44 are C32/f32 only); fractionally spaced and decision-feedback equalizers; 256-QAM and APSK; protocol stacks (TETRA downlink broadcast channels: the BSCH in [M57](M57-tetra-bsch.md), then the AACH, the BNCH/SYSINFO with the colour-code scrambling, the upper MAC with fragmentation and the LLC/MLE broadcast messages, see [tetra-decoder-gaps.md](../tetra-decoder-gaps.md); POCSAG, M17, DMR framing, FX.25, G3RUH 9600 Bd, APRS payload parser, ADS-B CPR positions and error correction, device decoders for OOK sensors); RDS error correction, RDS2, ODA/TMC; LoRa (CSS), OFDM (DAB, DVB-T, WLAN), spread spectrum.
  5. **DAB, then DAB+:** frequency and time deinterleaving (16 frames, about 384 ms: storage from the arena; which targets support it is a maintainer decision, for example one subchannel on Cortex-M), energy dispersal, the FIC (ensemble, services, labels), subchannel extraction with a demux convention for many services (`Fork` has two branches only: packets tagged with the subchannel and a small demux block), MP2 frames; DAB+ adds the superframe (firecode, RS) and AAC frames for an external decoder.
  6. **DVB-T:** scattered and continual pilots, TPS, the inner bit and symbol interleavers, the outer convolutional interleaver, RS, energy dispersal and MPEG-TS packets (188 bytes) as output for an external player; no video decoding in SDRk. Input rate 64/7 MHz for 8 MHz channels through `resample`.
- **A coherence criterion for the wideband rule of `band_pulse_detect` (from I45.1-8, D3166):** with 4 to 7 hearing lanes (a carrier deafens lanes) two constant-envelope transmissions of the same timing, each between two lane centres, can lift all hearing lanes but one and the second one is dropped as part of a wideband event. A further criterion that tells two transmissions from noise over the hearing lanes, for example the coherence of the lane signal over a block (high for a tone, low for noise) or the spread of the lanes' frequency estimates, is to be measured when a real recording shows the case; it costs cycles per lane value.
- **Analysis blocks** with structured results (frames/events): signal detection (frequency, bandwidth, level, SNR), occupied bandwidth, noise floor, burst detection, instantaneous values and histograms, symbol-rate estimator.
- **Digital modes after M44:** diagram data as frames (constellation, eye diagram); `sync_detect` (a sample-level preamble correlator; M37–M44 synchronize on bits); forward error correction (convolutional codes with Viterbi, Reed–Solomon, LDPC); CQ15/Q15 variants of the digital blocks (M38–M44 are C32/f32 only); fractionally spaced and decision-feedback equalizers; 256-QAM and APSK; protocol stacks (POCSAG, M17, DMR framing, FX.25, G3RUH 9600 Bd, APRS payload parser, ADS-B CPR positions and error correction, device decoders for OOK sensors); RDS error correction, RDS2, ODA/TMC; LoRa (CSS), OFDM (DAB, DVB-T, WLAN), spread spectrum.
- **Symmetric RDS blocks (noted with the names of M44.1, 2026-11-15):** the receive side has two kinds, `rds_demod` (the 57 kHz subcarrier to bits) and `rds_decode` (bits to groups), the transmit side one, `rds_encode` (groups to the shaped baseband of the subcarrier). By the naming scheme of M24.1 the transmit side would be `rds_encode` (groups to bits) and `rds_mod` (bits to the subcarrier), the pair of `rds_decode` and `rds_demod`, with `rds_encode` as the composite or the flows wiring the two. A hard rename without aliases (no aliases before 1.0); `fm_stereo_rds_mod` and the RDS flows follow.
- **Plans of the composite blocks (the original M32, moved here by D358):** for `ddc`, `duc`, `fm_demod`, `am_demod`, `ssb_demod` and `fm_stereo_demod` the same computation as a composition of primitive blocks with `Chain` and `Fork` (module `sdrk_blocks::plans`), equal to the block bit for bit on every backend, as an executable specification. Nice to have: the blocks are already checked against golden cases and kernel chains, and the first new composite block (M35) can be written as a plan when it is built.
- **Optimized square-root Nyquist pulse shapes (from M40, D626):** a `design` mode next to `rrc` for pulse shapes with lower intersymbol interference at the same length: a Kaiser-windowed RRC whose bandwidth is tuned so that `h * h` is close to Nyquist (as liquid-dsp's `rkaiser`, with the closed-form approximation of `arkaiser`), or a Harris-Moerder design; a parameter `shape` (`rrc`/`rkaiser`) of `psk_mod` and `psk_demod`. The truncated RRC leaves about -45 dB at span 10 (5.8e-3 at roll-off 0.35, 8 samples per symbol); a tuned Kaiser design reaches about -65 dB at the same length with a slightly wider effective roll-off. Build it when a mode needs more than -45 dB, for example dense QAM after M44, and gate it against liquid-dsp.
- **`biquad` with explicit coefficients (from M34, D398):** a mode of the kind `biquad` that takes `b0, b1, b2, a1, a2` per section instead of a response (schema mode, a stability check, the Q15 coefficient range), for filters the RBJ responses do not cover: the pre-emphasis of the FM stereo transmitter (M36), shelving and all-pass sections, designs from an external tool. Build it when a block needs it.
- **Composition (from M27–M34):** a generic kernel merge so that `fir_decimate` has a real variant (`FirDecimateReal`; M29 uses `resample_real` with L = 1 for now), shared kernel helpers (phase accumulator, one-pole, loop filter), `ssb_demod` built on `ddc`; a procedural macro that generates `Chain`/`Fork` compositions; a pipeline representation of composite blocks (`expand_composites`, group provenance, splitting a flow by groups); an adder for more than two inputs; fractional delay alignment; two clock domains in one pipeline (the `clock_domain` check of M34 rejects them); text parameters (`ParamKind::Text`; M42 sends PS/RT as packets); SigMF annotations for packets; packets above 256 bytes.
- **AFC on random data (from M39, D585):** an `afc` that follows a carrier drift without lag also on random data, for example a second-order loop (which may then average over a long time constant) or an update gated by the preamble; the first-order loop of M39 holds 50 Hz only on balanced signals.
- **Noise reduction and audio (from M33, M35, M36):** spectral noise reduction, a Q15 `auto_notch`, DSB with suppressed carrier, SSB by the phasing method, shaped CW keying, a speech compressor, CQ15 variants of `preemph_limit` stereo and `stereo_encode`, a composite clipper.
- **Real hardware:** the same `targets/` on boards via `probe-rs` (Cortex-M, ESP32 via `espflash`), DWT cycle counters / `mcycle`, real-time targets per platform (the plan defers them until hardware is in use).
- **Device API gaps** identified by the SoapySDR mapping in M12 (sensors, generic settings, frequency components, clock/time source selection).
- **Optional:** GStreamer-style shorthand for flows (`rf ! ddc frequency_hz=600e3 ! fm_demod ! out`) compiled to the JSON model; compiling a JSON flow into heap-free Rust code for MCUs.
